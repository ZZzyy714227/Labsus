# EXPLAINER-STANDARD — 讲义制作标准 v2

> 2026-08-22 起生效。来源：用户将第 2 讲交 Gemini 优化后确认"这个版本比较适合我学习"，
> 从 `第二讲.html` 提炼固化。模板：`learning/explainers/_template.html`（head+CSS+骨架，直接复制起稿）。
> 本标准替代 v1（暗色 plain HTML + ASCII 公式 + 无解析的检查点）。

## 一、文件与命名

- 讲义放 `learning/explainers/`，命名 **`第N讲.html`**（用户命名习惯，N=章节号）。
- 旧格式文件（ch01-*.html / ch02-*.html）保留为档案，不删；如需引用以 `第N讲.html` 为准。

## 二、技术底座（模板已内置，勿改）

- **MathJax 3**（CDN）：行内 `$...$`、独立 `$$...$$`；`skipHtmlTags` 排除 `code/pre`（代码块内不渲染）。
- 暗色主题 CSS 变量体系 + 语义组件类（见三）。
- viewport meta（移动可读）。

## 三、结构规范（每讲必有，顺序固定）

1. **H1 + 副标**：`第 N 章 · 标题`，副标 `LABSUS 悬架实验室 · 自底向上 N/11 · 主线名`。
2. **N.0 这一章解决的物理问题**：一段话说清"进来时有什么、出去时能回答什么"。
3. **💡 核心矛盾**（`box intuition`，紫）：先物理图景，后形式化——直觉先行。
4. 正文，四种语义盒严格分工：
   | 盒 | 类名/色 | 用途 |
   |---|---|---|
   | 💡 直觉/工具 | `box intuition` 紫 | 核心矛盾、几何直觉、关键工具卡 |
   | 📐 推导 | `box proof` 绿 | 零跳步数学推导 |
   | ⚠️ 警示 | `box warn` 黄 | 陷阱、物理不可能、工程纪律、真实事故 |
   | 🎯/⚖️ 算法/架构 | `box algo` 蓝 | 问题形式化、架构对比（配表格） |
5. **多步推导用 step-card**：`Step 1..N`（或 `定义`/`旋转运算` 等语义 tag）一步一卡。
6. **关键公式进 `formula-highlight`**（一讲中最终结论级公式）。
7. **代码对账**：真实源码 + 语法高亮 span（`keyword/func/comment/num`），每行注释对应推导步骤——"每一行都对应推导的一步，没有魔法"。
8. **数值实验表**：真实运行得到的数字（禁止编造），以表格呈现。
9. **检查点 qa-box 带解析**：问题 + `<b>解析</b>`（含答案要点）——自学模式，读完即自测。

## 四、内容规范（继承不变）

- **零跳步推导**（用户核心要求："基础知识都知道，但是你不能跳过"）。
- 每个数学对象落到项目真实代码与真实数字（file:function 级定位）。
- 中文行文，术语中英对照。
- 图不必须；若画，必须由生成器从真源计算（`learning/tools/gen_views.py` 流程），禁手绘。
- 历史真实 bug 是首选教具。

## 五、制作流程

1. 复制 `_template.html` 起稿；
2. 写内容（先跑数值实验拿真数字，再写正文）；
3. playwright 验证：MathJax 公式渲染数 > 0、零 JS 错误；
4. 学习记录同步（`learning-records/`）。
