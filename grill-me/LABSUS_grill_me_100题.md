# 参考答案（方向一）

**1.** 合格要点：Three.js 用于第一代 3D 预览（线框 + 小球，LineBasicMaterial/MeshLambertMaterial）；放弃的真实动因通常是组合拳：单文件双击即用的部署诉求 vs Three.js 的依赖引入（CDN importmap 断网不可用 / npm 需构建链）；渲染本身不是瓶颈。能给出具体版本、引入方式和至少一次缓解尝试（如按需渲染）即为合格。承认"Three.js 没死在性能上，死在部署形态上"是最诚实的答案。

**2.** 合格要点：确认全手写——正交视图 `dot(p,bx)` 线性投影，透视视图针孔模型 `f=dist/z`；近平面 z<80 直接丢弃点。线段穿近平面确实会出反向飞线/丢线，正确修法是对线段两端做参数插值裁剪（t = (80 - z0)/(z1 - z0)）；承认当前实现是 demo 级裁剪是加分项。Canvas 2D 够用因为图元是数百量级的 2D 路径，不是万级三角形。

**3.** 合格要点：能报出三代的时间线、代码规模（单文件版 348KB / 内置引擎版 216KB）、每代保留的东西（矢量数学库 add/sub/dot/cross、HP_META 硬点元数据、四视口布局是从一代延续下来的）。重构判据：allinone 双击可用（车队赛场无网）；fullchassis 对接后端满血 K&C。承认 348KB 单文件是刻意的部署取舍而非最佳工程实践。

**4.** 合格要点：拖拽时 `rebuild()` → `driveTo`：把轮心目标 Z 差分成 `min(28, ceil(|d|/4))` 步、每步 ≤4mm 延拓，中间步 maxIt=40、末步 260，tol=2e-7；这是 continuation 法——用上一步解作下一步初值，避免一步跳变大位移时投影迭代落入错误装配分支。一帧 50mm 会走 13 步左右仍在单帧内完成（JS 求解毫秒级），视觉上是即时贴合；速度极快时可能短暂显示中间姿态。拖拽全程走前端 JS 引擎，不发网络请求。

**5.** 合格要点：残差是杆长误差的 max-范数（无穷范数，单位 mm）+ 轮心 Z 驱动残差取 max；选 max 是保证最坏约束达标，代价是收敛尾部抖动、无平滑梯度。tol=2e-7mm 用于迭代提前退出，最终判定 M.ok 用 0.025mm 宽容差（投影迭代精度现实）。`(it&3)===3` 每 4 次才算残差省约 75% 残差计算。JS 投影迭代解等式约束（杆长=定值），Python TRF 解非线性最小二乘（残差平方和），两者问题定义不同、残差范数不同，parity 脚本比对的是同输入下最终节点坐标/定位角，容差需自己能报出。

**6.** 合格要点：机构数据全局单份（SIM.FR/RR/FL/RL），四视口只持相机参数（VW 数组：s/cx/cy/az/elv/dist）；联动 = 数据共享，不是消息广播。每帧 `loop()` → `simulate(dt)` → `drawAll()` 四视口全量重绘 → `updateReadouts` → `drawPlots`，无脏区。K&C 扫掠在 `updateSweeps` 里 140ms 节流 + 45 步，与拖拽同线程但被节流保护；拖拽期间扫掠最多每 140ms 插入一次约几十 ms 的批量计算，实测帧率会抖但可接受——能主动说出"没做 Web Worker 隔离是已知短板"加分。

**7.** 合格要点：PICK 在绘制阶段由 ND 图元投影时填充（视口相关）；投影 null（近平面后）的点不进 PICK 或拾取异常，是已知盲区。屏幕重叠时选距离最近者，无深度消歧——正视图里前后轮硬点重叠会选错，靠镜像开关（show.mirror）规避。透视视口禁拖的原因：屏幕位移 → 世界位移需要除以深度 z，透视下同一像素位移对应不同深度的不确定位移，正交视图有固定基向量 bx/by 和比例 s 才能唯一反解。

**8.** 合格要点：`da/db` 是像素位移除以 s（px/mm 比例）得视图平面内毫米位移，再按 bx/by 基向量合成世界向量；镜像侧 X 翻号因为左右对称硬点的世界 X 与屏幕 X 方向相反（Y/Z 轴向不随镜像翻转）。滚轮用幂函数 `1.0015^(-deltaY)` 是因为滚轮 deltaY 离散值大，指数映射手感均匀且无极跳；clamp [0.02,15] 防过度缩放后拾取/拖拽数值失稳。0.1mm 量化让显示与求解输入一致，避免浮点尾数触发无意义的机构重解。

**9.** 合格要点：画家算法——图元按到相机（或视图法向）距离排序后从远到近绘制；每帧排序数百图元，Array.sort O(n log n) 完全无压力。半透明面排序敏感（透明面不写深度在 Canvas2D 里表现为叠加顺序即绘制顺序），承认存在排序错乱的已知 case（如摇臂与弹簧重叠）。能举出实例（如推杆穿过 A 臂时闪烁）并说明修法（微调排序 key / 拆分图元）为佳。

**10.** 合格要点（数字量级，允许 ±50%）：单轴模型约 20+ 节点 / 20+ 杆件；`solveKin` 典型 5–20 次迭代、几十微秒到 1ms 级；`driveTo` 大位移时 <5ms；每帧预算里求解 <2ms、四视口绘制 2–6ms、DOM 读数更新 1–2ms。FPS 统计是 0.4s 窗口计数写 `#tbFps`。内存：长期运行的主要风险是 sweep 数组与 plots 画布重建，应能说出测量手段（DevTools Memory 快照对比）。任何"没测过但很快"都判不合格。

**12.** 合格要点：JS 侧拥有拖拽闭环所需的姿态求解（投影迭代）+ 准静态扫掠 + 4-Post/爬坡/绕桩的简化动力学（TPHYS）；Python 侧拥有满血 K&C 三工况、整车 chassis/solve、赛道瞬态 simulate_track（TRF + 衬套 6DOF + Pacejka）。双实现动机：赛场无网时 allinone 仍可用；一致性由 tphys_parity.cjs 把关。代价：同一物理两处维护，任何建模改动要双写——能举出一次具体分叉（如 motion ratio 定义差异）最有力。

**13.** 合格要点：超时与计算量成正比：health 探活 4s、K&C 扫掠（~45×3 步 TRF）60s、整车 chassis 90s、赛道瞬态（数百时间步）120s。请求期间状态按钮/面板锁定或显示 pending；AbortController 用于超时中断。承认"请求在飞、用户继续拖硬点"存在竞态（响应回来覆盖新状态），当前以"分析操作与拖拽分属不同面板 + 用户自律"规避是诚实答案，说出"应加请求序号丢弃过期响应"是加分。

**14.** 合格要点：`S` 是用户输入态（硬点/工况/播放），`SIM` 是求解态（机构、扫掠、动力学），`UI` 是交互瞬态（hover/drag/sync）——单向：S 改 → rebuild 写 SIM → 绘制读 SIM。`UI.sync` 是每帧全量执行的同步回调数组（读数条、硬点表回填），因为回调总量几十个、每个都是轻量 DOM 文本写，实测无感；承认它是"每帧轮询"而非响应式。Undo 的难点：deepClone JSON 方式对大状态慢且丢失引用关系，SIM 含四元数/迭代器状态不可 JSON 化——需要区分可 Undo 的 S 层快照与派生的 SIM。

③ 翻车案例：toe-in 为正 vs ISO toe 角定义、外倾负=内倾的约定、侧倾角正=向外倾还是向内倾——你在左右镜像时踩过哪些符号坑（K-1 scrub 不对称 bug 的根因）？
④ 单位制：接口里 mm/m/N/kg 混用（travel mm、trail mm、Ls m、Fz N）——谁负责换算？Pydantic 模型里有没有单位字段声明，还是纯约定？

**考察点**：多坐标系与单位约定是仿真软件最隐蔽的系统性风险。
**不合格判定**：不知道自己仓库里有两套轴向声明或说不出映射关系；分不清 SAE/ISO 在 z 轴方向与角速度正方向上的差异；镜像翻号没有成文的规则（哪些向量分量翻、哪些角度不翻）。

# 参考答案（方向三）

**51.** 代码实际四工况 = bump（平行轮跳，位移控 ±30mm 步 2mm）/ roll（左右反向行程，位移控）/ steer（齿条位移控）/ compliance（衬套锚点力控）。与商业台架"平行/同向轮跳+侧向力+回正力矩"不完全等价：侧向力/回正力矩工况被 compliance（直加锚点力）替代，未做轮心六分力路径。答不出驱动方式/量级或把四工况混背成台架标准工况→不合格。

**52.** Camber = −atan2(spin_z, hypot(spin_x, spin_y))（负=内倾，全局约定）。°/25mm = 25×(γ(x+2)−γ(x−2))/4mm，即 ±2mm 中心差分窗口（metrics/kandc.py `_slope`）。强非线性应报多点斜率或分段；0.1–0.2mm 残差在 4mm 窗口上差分可能引入 % 级斜率噪声，需先平滑或加窗。

**53.** Bump steer = 轮跳引起的 toe 变化，几何上由转向拉杆内外点与双叉臂轴线的投影共线度决定（拉杆与 LCA 轴线在侧视/俯视瞬心重合→零 bump steer）。提取：heave 扫掠锁 rack=0；toe = −side·atan2(fwd_y, fwd_x)，toe-in 为正、左右统一车辆全局约定（平行转向时两侧异号是物理正确）。FSAE 目标 |≤0.3|°/25mm，<0.5 可接受；与 Ackermann 区分：bump steer 在 rack=0 的 heave 扫掠中测量，Ackermann 在 steer 扫掠中测。

**54.** 运动学 RC：前后叉臂轴线定 IC，IC 与轮心连线交地面（对称面投影）。力法 RC：左右侧向力作用线与垂向力偶合成作用线交地面；线性小侧倾下两者一致，衬套柔性/大侧倾分歧。整车 roll axis = 前后轴 RC 连线，侧倾角绕它。FSAE：前 RC ≈15–40mm、后 ≈40–80mm（后高于前促稳定）。大侧倾/叉臂近共线时 IC→∞，实现需角度阈值检测+虚拟点截断。答不出双定义或奇异处理→不合格。

**55.** RC 迁移根源：上下叉臂长度差→虚拟摆臂长度随行程变化→IC/RC 高度漂移。±30mm 工作段迁移 <10–15mm 算干净，>30mm 设计缺陷（侧向力作用线大幅变动、操纵特性漂移）。修正手段：拉长上叉臂（虚拟摆臂加长）、调叉臂内点高度差。要能报出自己前后轴的实测迁移数。

**56.** °/1000N 归一。典型：compliance steer 0.05–0.3°/kN（球铰悬架偏低端），0.5°/kN 已明显偏软；后轴设计成侧向力下 toe-in（不足转向趋势）。代码自认 S1 是"单锚点直承外载"，接地点→二力杆→锚点的力分配（T5）未完成，故与真实悬架的 C 特性存在载荷路径系统偏差。衬套径向数百~数千 N/mm、轴向更低；球铰间隙才是 FSAE compliance 主源。力扫量级 ±1–2kN 内线性近似成立。

**57.** 线性 k·δ 失效场景：幅值相关（大载荷刚度 +30–50%）、径向-扭转耦合、预紧。准静态下频率相关可忽略。六项刚度：平动 ~几百–2000 N/mm、转动 ~10–100 N·m/rad 量级，来源应为 datasheet 或实测，说不出来源即扣分。k→∞ 时外层位移→0 自动退化为纯 K 求解（应能自证此极限行为）。

**58.** 外层变量 δ（每衬套 6DOF），残差 r(δ)=f_ext−Kδ（N，或 N·m）；TRF=带箱约束信赖域，LM 是阻尼最小二乘无箱。阈值：外层代价 <1e-6 → VALID、>1e-3 未收敛 → DIVERGED、内层 KIN_TOL=1e-10、KIN_MAX_NFEV=200；Anderson 兜底 β=0.5、m=3、40 步、tol 1e-6、步长限幅 5mm。APPROXIMATE=力平衡方程超静定（铰约束数>独立平衡方程），取最小范数解——物理上对应"约束内力分布不唯一"。步长限幅 5mm 可致假收敛（残差卡在限幅循环）。DIVERGED 必须向上传播给调用方，静默降级=不合格。

**59.** 可信验证链（无商业软件时）：①解析退化（平行四边形/等长叉臂→camber/toe 恒 0）；②镜像对称测试（tests/test_mirror_symmetry）；③手算瞬心/RC 对拍；④公开基准模型曲线。对 Adams 报表复现需：完整硬点表、衬套刚度表、加载定义与归一化方式。声称"与商业一致"却无一条误差数字（如 camber gain 差 <5%）→不可自证，不合格。

**60.** K-4：负行程侧机构求解分支锚定的软项妥协，polish 残差 −10mm≈0.10mm、−15mm≈0.19mm（目标 ≤0.02mm），负/正不对称源于雅可比条件数随行程恶化。误差传播：0.1mm 级坐标噪声 ÷4mm 差分窗 → 斜率噪声 ~2.5% 级，对 camber gain/bump steer 这类小斜率指标不可忽略；瞬态 LUT 查表时以系统偏差形式进入。锁基线（test_hand_benchmark）只是冻结现状防回归，不等于修复。

**61.** 若简历写 4-Post 必须能落到实现：输入=四轮垂向位移谱（正弦扫频 0–25/30Hz 或道路 PSD 时程）；相位矩阵：heave 同相（簧上共振）、roll 左右反相（侧倾模态）、pitch 前后反相（俯仰模态）、warp 对角反相（扭转刚度）。输出：簧上/簧下加速度 FRF、车轮动载荷、共振峰位置。引擎内无独立 4-Post 模块、逻辑在前端 JS（TPHYS）时，必须主动说明双实现一致性与局限，含糊其辞或谎称独立模块→不合格。

**62.** 每角 2-DOF：f₁,₂ 由 (k_s·MR²/m_s) 与 (k_t/m_u) 定。FSAE 簧上偏频 3–5Hz（民用车 1–1.5Hz），因抓地/响应优先、行程度小；簧下 ~10–15Hz；阻尼比 0.3–0.7。口算例：f=(1/2π)√(50e3·0.75²/60)≈(1/2π)√469≈3.4Hz。前后轮输入时差 = 轴距/车速 = 1.55/15 ≈ 103ms，与 3–4Hz 模态周期（~300ms）同量级→前后相位差显著影响俯仰激励。口算不出→不合格。

**63.** 真实减振器：回弹峰值约为压缩 2–3 倍、分段线性+阀开启非线性。c_wheel = c_damper·MR²。例：c_damper=3 kN·s/m、MR=0.75→轮端 1.69 kN·s/m；ζ = c/(2√(k·m))，k=37.5kN/m（折算后）、m=60kg→ζ≈1690/(2·1500)≈0.56，合理。非线性下 4-Post 线性 FRF 失效，需谐波线性化或时域积分。

**64.** MR = |d(damper)/d(wheel)|，±2mm 中心差分（窗口小、含非线性一阶项）。OpenItem-B：rocker 双解分支（最近根 vs 投影全局解）选择不稳，前端常量 0.75/0.78 与引擎差分值 0.47/0.17 差异巨大且后轴实测可为负号（pullrod 压缩时减振器伸长）——下游只用 mr² 故取 abs。MR 差 20% → 刚度/阻尼差 1.2²=1.44（+44%）。分支错误表现为 MR(travel) 曲线跳变；曾出现 RK_DAMPER 不更新→MR 失真 3.98 的 bug。

**65.** 模型：车体 3-DOF（纵/横/横摆，6 状态）+ 每轮一阶轮胎状态（松弛 α_lat）+ 准静态侧倾/俯仰经一阶滞后（τ_roll/τ_pitch）滤波后用于 K&C LUT 行程索引。辩护：7-DOF 垂向贵在刚度耦合刚/病态+步长压缩，且 FSAE 关心的操纵瞬态时标（>100ms）与侧倾建立（~50ms）可用滤波近似。τ 量级 ≈1/(2πf_roll)≈30–50ms。失效：高频转向修整（<0.5s）、路面激励叠加、侧倾-横摆耦合接近共振时准静态失真；roll 峰值削平 → LUT 行程低估 → γ/Fz 双误差，Fz 误差更致命（轮胎力平方级敏感）。

**66.** 离线查表：K&C 扫掠预生成 travel→指标 LUT，步内 np.interp。在线 solve_pose 单次毫秒级×四角×每步不可行（10s@5ms=2000 步×4 角×毫秒级=数十秒起）。np.interp 越界端点常值外推→行程超 ±30mm（打限位）时指标冻结，需告警。单变量 travel 索引下每轮用各自行程查本侧表，roll/heave 耦合近似为行程叠加。LUT 为纯 K（无衬套力）→C 效应未进瞬态，应显式声明。

**67.** Fy = D·sin(C·atan(Bα − E(Bα − atan Bα)))，D=Fy0·(Fz/FzNom)·(1−LS(r−1))。D 峰值、C 形状（1.2~1.3 侧向）、B 刚度、E 曲率/峰值后形状。默认 Fy0=8000/FzNom=3500 → μ=2.29，明显高于 FSAE 干胎 μ≈1.4–1.7（Hoosier R25B），说明默认参数未按真实轮胎校准——能主动指出此问题才是合格回答。Mz = Fy×固定 trail 60mm 为 APPROXIMATE 占位：真实气动拖距随 α 增大而收缩、随 Fz 变化，大滑移角下 Mz 形状全错。

**68.** 松弛长度：接触印迹经胎侧柔度逐步建立变形，侧向力需滚动 Lσ 距离才达稳态的 63%。τ=Lσ/vx：10m/s→35ms；2m/s→175ms，低速大转角 Fy 严重欠冲+相位滞后，可能出现超调。vx→0 奇异：实现需 v 下限（如 1–2m/s）或切换非稳态刷子模型。相位滞后贡献：低速时松弛主导，高速时 roll/pitch 滤波与松弛同量级（几十 ms）。

**69.** 摩擦圆法：lat_avail=√((μFz)²−Fx²)，纵向优先、Fy 形状在极限附近偏保守；MF combined slip 用复合滑移向量+Gij 修正，极限处 Fy 衰减更真实。Fx 由动力需求给定（非 κ 反解）是因果倒置的简化，仅适合不打滑工况；Fx>μFz 时 clamp 到摩擦圆（lat_avail clamp ≥0）。例：μ=1.5、Fz=1500N、Fx=1500N → 剩余 √(1.5²−1)·1500≈1677N ≈ 峰值 2250N 的 67%——口算必考。

**70.** 外倾推力 dFy/dγ ≈ 0.3–0.8·Fz /rad（FSAE 小胎偏低端），Cg≈0.5 1/rad 合理但 γ 来源若为设计常数而非 LUT 则降级。LS：载荷敏感性，LS=0.1→载荷翻倍 μ 约降 10%，默认 0（关闭）。外轮 Fz↑ 且负 camber：外倾推力补偿部分载荷转移损失，两效应部分抵消。校准需 Hoosier 变载荷 Fy-α 曲线族（CVD/Milliken 数据）拟合 D(Fz) 与 dFy/dγ。

**71.** φ = m·ay·(h_cg − h_rc_f·W_f/m/g −…) 简化为 φ = M/K_φ，M=m·ay·(h_cg−h_rca)，K_φ=K_φf+K_φr（弹簧 kS·MR²·(t/2)² + ARb + 衬套折算）。FSAE 目标 1.0–1.5 deg/g（激进 0.5–1.0）。三轮迭代：侧倾→RC 迁移（rc_h sweep 插值）→力臂/刚度变→重解侧倾，收敛判据为相邻轮 φ 差 <1e-3 级。TLLTD = 前轴份额（K_φf 与前后 RC 高度项加权），决定稳态转向平衡（前份额大→不足转向）。h_cg≤h_rc 或 K_φ→0 时代数解奇异/无意义，需防御；anti-geometry（jacking）未建模应声明。

**72.** 赛道=中心线点列+曲率；pure pursuit Ld ∝ vx（如 0.5–1s 前视）。目标速度 v=√(a_lat_max·R) 由曲率定，PI 消稳态误差。可输出：轨迹误差、每轮 μ_use、apex 速度、瞬态响应曲线；lap time 需纵向最优策略/胎温/赛道 grip 分布，答"能出 lap time"却无纵向策略→夸大。标准项目对标：skidpad R=15.25m 双圈计时、直线加速 75m——模型应能给出这两项的 g 值/时间并与实车对比，至少做过 skidpad 稳态 ay 校核。

**73.** 最快时间常数：高速时松弛 τ=Ls/vx（30m/s→12ms）。固定步长 dt=2–5ms，显式 Euler 稳定需 dt<2τ：dt=5ms、τ=12ms 时裕度仅 2.4 倍，逼近临界。prev_ay 显式耦合（载荷用上一步）在 dt 过大时可产生载荷-侧倾数值颤振（伪 2 步振荡），出现于 dt 接近系统周期一半时。10s@5ms=2000 步，纯向量化 Python 约 0.5–2s 量级；瓶颈在 per-step 的准静态载荷链与 MF 四轮求值，优化靠预计算/缓存 LUT。

**74.** chassis 层是 per-corner 局部系（X 外侧/Y 向前/Z 上），整车层经 make_corners + mirror_left（x→−x、steer_axis 反号）映射；镜像翻号规则：坐标/横向力分量翻号，toe/camber 用 side 因子统一为全局约定（convention.py：X 前右上前轴原点，camber 负=内倾、toe-in 正、caster 正=上端后倾）。SAE J670 z-down vs ISO 8855 z-up：横摆角速度 r、侧倾角正方向两标准相反，本仓库 Z-up+自定义符号在 CoordinateConvention 元数据中冻结（v1-p2-0）并配 test_convention.py。K-1（scrub 镜像不对称）即旧坐标外倾公式+横向偏移的符号坑实例。单位 mm/m 混用无 Pydantic 单位字段=纯约定风险，应承认。

**75.** 参数溯源分级：质量/轴荷——地磅实测最优、CAD 次之；Iz≈100–200 kg·m²（FSAE 常按回转半径 0.8–1.0m·√(m) 估算或实测扭摆）；弹簧——标称值 vs 实测曲线需区分；衬套——datasheet 或假定；轮胎 MF——公开数据拟合（CVD）或假设值（默认 Fy0/FzNom=2.29 即未校准的证据）。解析闭环：稳态回转 understeer budget K_us = W_f/C_αf − W_r/C_αr ± 前后 RC 项/ARb 项，模型稳态回转输出与手算对拍误差应 <10–15%。能量校核：4-Post 输入功=阻尼耗散+势能变化。极端参数测试：衬套 k×100→C 指标趋 0、K 指标不变；μ→0.8→ay_limit 按比例降、轨迹发散；LUT 置默认→瞬态 γ/RC 响应改变。答不出"哪些必须变"=模块未真正耦合，不合格。
