**26. [难度5] 你简历写"自研多体机构求解方法（闭式投影迭代与最小二乘 TRF 联合收敛）"。但 `mechanism/solver.py` 的模块 docstring 第一段白纸黑字写着：收敛"不改用独立精确投影迭代（实测在真实几何、双闭环/强各向异性协方差下 Gauss-Seidel 不收缩），而是对同一套约束残差向量做 scipy least_squares 联合最小二乘"。请先回答：闭式投影迭代到底是被"联合使用"了，还是被你放弃了？**

**回答**：**结论先说：在 Python 引擎主路径上，闭式投影迭代被放弃了，"联合收敛"是我在简历里对一段探索史的修辞，这一点我不辩解。** `solver.py` 第 3–10 行的 docstring 就是最终结论：收敛方式是"对同一套约束残差向量做 scipy least_squares 联合最小二乘"，投影迭代只活在注释里的"已记为有据偏差"。主路径是：`solve_pose` → `least_squares(fun, x0, method="trf", xtol=ftol=gtol=1e-10, max_nfev=200)`，摇臂再用 60 次二分法串联后处理。代码里唯一还活着的投影算子在 `mechanism/project.py`，以及前端 JS 引擎（`web/dwb-pro-fullchassis.html` 的 `sweepProj`/`solveKin`）——也就是说投影迭代并没有消失，但它不在 Python 求解主路径上。

(a) 被放弃的投影迭代数学定义（project.py + JS 引擎同构）：每轮 Gauss-Seidel 顺序执行五类投影——
- **刚线/拉杆定长**（`project_distance`）：误差 C=‖b−a‖−L0，沿杆向向量 d 按逆质量加权分配：`A.pos += d·(C/(‖d‖·(wA+wB)))·wA`，`B.pos -= d·(...)·wB`，即两端各收编一部分误差使长度恰为 L0；
- **铰链簇**（`project_axis_rotation`）：把成员点绕过 anchor 的单位轴 u 做单参数最优旋转，闭式解 θ=atan2(Σk wk⟨u×rqk, dk⟩, Σk wk⟨rqk, dk⟩)，其中 rqk 是设计偏移的垂直分量、dk 是当前偏移。绕轴旋转天然保持轴向坐标和半径，所以这一步同时把成员锁回"以轴线为心、半径 r0 的圆上"和"轴向坐标 ax0"两条约束——轴向坐标不是另外锁的，是旋转投影的不变量；
- **转向节刚体**（`project_body`）：质量加权协方差 A=Σ wk·(p−c)·relᵀ，极分解取旋转（Müller 四元数迭代，步长异常 w>2.5 时回退 SVD 正交 Procrustes），成员重置为 c+R·rel；
- **摇臂**（JS `projRockerStrut`）：推杆定长下绕枢轴转角的闭式圆-线相交解，θ=φ−branch·ψ，cosψ=C/hyp（余弦定理），Python 侧最终退化成二分法。

(b) "Gauss-Seidel 不收缩"的实测背景：双闭环指**推杆-摇臂环**（UP4→CH5→摇臂→减振器）和**横拉杆-齿条环**（UP3→FL1）这两个通过从动链闭合的回路，加上转向节刚体与上下臂铰链的强耦合。真实几何下两个问题的叠加：一是基线 X 跨距 358mm 这类强各向异性使各约束的敏感方向差 2~3 个数量级，交替投影互相破坏——轮高刚投完，拉杆投影把它拉走，刚体投影又破坏铰链；二是逐约束投影没有全局下降保证。当时观察到的残差行为是：快速降到 0.1mm 量级后进入平台/极限环震荡，数百轮内进不了 0.02mm。诚实地说：当年的残差曲线序列我没有存档，现在能给的三条硬证据是——docstring 记录的结论、JS 引擎至今要用 maxIt=260 且每 4 轮才查一次残差（`if((it&3)===3)`）、以及 JS 引擎的成功阈值放宽到 `M.ok=res<0.025`，而 TRF 在同一几何下 4 次 nfev 到 5.8e-12mm。我不再把"步长没调好"当借口，这是算法层面的收缩性问题。

(c) 我认：简历那半句经不起逐字拷问。现在敢说的"联合"只剩两件真事：一是**同一套约束残差向量**（hinge+刚体+拉杆+轮高+FL1）同时喂给 TRF 做联合最小二乘，而不是逐约束投影；二是闭式投影算子作为原语还活在前端引擎和 project.py 里。准确的表述应该是："多体机构约束求解：以联合最小二乘（TRF）替代交替投影迭代，闭式投影算子保留于前端实时引擎与初始化原语"。我会在下一版简历里改掉。

**27. [难度5] 把你内层机构的残差向量逐条背出来：18 维状态（UP1–UP5 + FL1 各 3 坐标）对应多少条残差？每条的物理含义、单位、量纲各是什么？**

**回答**：**结论：残差全部是毫米量纲的几何等式；条数随拓扑变化——PRO 基线（strut_attach="knuckle"）实测 19 条对 18 个未知量，超定 1 条；strut_attach 为 lca/uca 时恰为 18 对 18，恰定。** 逐条构造在 `_build_residual`（solver.py:53-100）：

- **hinge 簇**：每个成员贡献 2 条——`distance_point_to_line(p, a, b) − r0`（径向：点到当前轴线的距离与设计半径 r0 之差，mm）和 `dot(p − a.pos, u) − ax0`（轴向：点在轴向上的投影与设计值 ax0 之差，mm，u 是当前轴单位向量）。r0/ax0 在闭包里按 p0 预先算死。默认拓扑下臂成员 [UP1]、上臂成员 [UP2]，共 2×2=**4 条**；
- **刚体距离对**：由 `m.bodies[0].ids`（默认 UP1..UP5 共 5 点）两两组合，C(5,2)=**10 条**，每条是 `‖pi−pj‖ − ‖pi0−pj0‖`，mm；strut_attach 为 lca/uca 时 UP4 移出刚体（4 点 C(4,2)=6 条），并追加一条 UP4↔driver 刚距（+1 条）；
- **拉杆**：`‖TIE‖ − L0`，**1 条**，mm。注意推杆 PUSHROD 虽然在 m.links 里，但不进残差——它由摇臂后处理解决；
- **轮高驱动**：`z − (z_p0 + travel)`，**1 条**，mm；
- **FL1 齿条驱动**：3 条直接坐标等式 `pos − (steer_anchor + rack·steer_axis)`，每条 mm。

合计（knuckle）：4+10+1+1+3=**19 条**；lca/uca：6+6+1+1+1+3=**18 条**。18 个未知量配 19 条方程是轻度超定，TRF 给最小二乘解——这条冗余来自"5 点刚体 10 条距离对"本身已把刚体姿态完全锁死，冗余不致病（相容）。

(a) 以上就是完整清单，全部 mm。 (b) **没有做加权归一，也不需要**：残差里没有无量纲项混入——hinge 两条是 mm、刚距对是 mm、FL1 三条是坐标差也是 mm。量纲一致正是它不需要加权就能收敛到 0.02mm 的前提。真正的量纲失衡在 compliance 外层（N 与 N·mm），那是另一题（36 题）的问题。 (c) 收敛判定 `ok = max|res| < 0.02`（solve_pose:177）用 max 范数，而 TRF 最小化 0.5‖r‖²（L2）。不一致的后果方向是明确的：19 条残差里若有一条卡在 0.05mm，L2 范数只有约 0.05（cost 约 1.2e-3），对 L2 目标而言"几乎收敛"，但 max 判据会正确地判 ok=False——所以我的判定在安全侧。反向风险是 TRF 的 ftol 基于 L2 下降提前终止而某条残差还大，实测中我没遇到过被放过的情形，因为 xtol=gtol=1e-10 比 0.02mm 的判据紧得多；真正抓出过失败的是 find_limits 场景：拉杆不可达时 max 残差跳到毫米级以上，被 thr=0.03 拦下。

**28. [难度4] 标准多体动力学教科书路线是拉格朗日乘子 + DAE 求解（或 Baumgarte 稳定化）。你的求解器里乘子在哪？如果有人说你这不是"多体动力学"而只是"约束位置问题的非线性最小二乘"，你怎么反驳？**

**回答**：**我不反驳定性——它就是位置级（零阶）约束问题的非线性最小二乘，我的反驳只针对"这不值钱"的暗示：这是 K&C 问题的正确抽象层级。** 我的求解器里没有乘子：没有拉格朗日函数、没有 λ、没有 Baumgarte——`solver.py` 全文只有残差函数和 least_squares。

(a) 约束全是定长/定轴几何等式，没有速度、加速度级约束。K&C 扫掠的漂移控制靠的是**每步独立重解**：`drive_to` 把轮跳拆段，每段从上一段收敛态热启动重新解全量约束方程，任何一步的残差都被压到 0.02mm 以下再前进——不存在"误差沿积分积累"这回事，因为没有积分。代价是我确实没有惯性状态，做不了真正的动力学，这正是我用瞬态层（transient.py 的 3-DOF 平面模型）另起炉灶补的。

(b) 超定时（刚距对与 hinge 约束相容冗余，如 27 题的 19 对 18）`least_squares` 收敛到最小范数最小二乘解。和乘子法的关系是标准的 KKT 等价：min ‖m‖² s.t. A·m=f 的解是 m=A⁺f（伪逆），而带乘子的平衡方程解出的约束反力分配同样满足最小范数条件——TRF/Gauss-Newton 在相容超定系统上收敛的解落在同一解集里。力学上对应"约束反力按最小范数分配"，我在 42 题会承认这个分配对悬架载荷问题恰恰是物理上不合理的假设。

(c) 不用 MBDyn/PyDy 的技术理由：K&C 需要的是"毫秒级、可热启动、分支连续"的准静态扫掠——前端拖拽是 16ms 帧预算，`drive_to` 每步都从上一姿态出发。DAE 积分器带惯性状态和指标约化，位置初值无法直接热启动，步进还会积累约束漂移（ Baumgarte 就是为这个发明的）；PyDy 定位是符号推导多体动力学，没有我这个"位置级投影+continuation"的现成求解模式。对这个用途，DAE 框架是拿大炮打位置级准静态问题，还打不准拖拽的实时性。 Adams/Car 是工业黑盒，我自研的是教育白盒——这是我敢把残差方程逐条背出来的原因。

**29. [难度4] `drive_to` 做了 continuation：`step=6.0`、`max_steps=24`，把目标轮跳拆成至多 24 步逐段热启动。请推导：从 0 到 160mm 需要几步？每步 TRF 的初值是谁？如果去掉 continuation 一步跳 160mm，最坏会发生什么？**

(a) 现场算过了：24 步、6.67mm/步。 (b) 大步长下会跳分支的拓扑：推杆越过死点构型（摇臂转角选另一支）、摇臂过中心反转（bracket 搜索在 ±3.1rad 内找到变号点但选错方向）、转向节绕主轴的镜像翻转——表现是 K&C 曲线上 Camber/Caster 突跳几十度。`find_limits` 确实用残差>thr=0.03 当分支跳变探测器（solver.py:216、224），但我要主动补一刀：**这个探测器只能发现"不可达"，发现不了"跳到另一个可达分支"**——镜像解同样满足全部约束、残差同样小于 0.02，残差判据对它完全失明。真正的分支防护应该是输出量连续性校验（相邻步 Camber 差超过阈值就报警/回退缩小步长），这个我还没实现，是 find_limits 的已知短板。 (c) 0.02~0.03mm 灰色带：ok 判据是 0.02，find_limits 的可达判据是 0.03，中间带的姿态会以"低精度但被当作可达"进入限位结果乃至 K&C 曲线。对用户的解释我不能说"没影响"——正确做法有三条：把 find_limits 的判定提到 0.02 与 ok 同源；对 0.02~0.03 的步自动减半步长回验；或在该步结果上打可信度降级标记。三条我都没做，当前唯一缓解是 API 层返回了 residual_mm 字段，用户技术上能看到每点残差，但没人会去翻。

**31. [难度5] `solve_pose` 的调用是 `least_squares(fun, x0, method="trf", xtol=ftol=gtol=1e-10, max_nfev=200)`。请分别解释 xtol、ftol、gtol 各自终止什么，以及 max_nfev=200 是"200 次迭代"还是"200 次函数评估"——这两者的区别在数值雅可比下有多大？**

**回答**：**先纠正题干里一个前提：按 scipy 官方文档，对 TRF 方法，`max_nfev` 计的是残差函数评估次数，且明确"不把数值雅可比的函数调用计入 nfev"（`least_squares` docstring 原文：Methods 'trf' and 'dogbox' do not count function calls for numerical Jacobian approximation）——所以"200 次 nfev 只够约 10 个 TRF 迭代"这个说法对我的调用不成立，200 次 nfev 大约等于 200 个可用迭代步；数值雅可比的 18 次差分评估藏在 njev 里，真实评估总量 = nfev + 18·njev。** 三个终止条件：`xtol` 终止变量步长（判据是 ‖Δx‖ ≤ xtol·(xtol+‖x‖)，相对形式）；`ftol` 终止代价相对下降（actual_reduction < ftol·cost）；`gtol` 终止一阶最优性（Jᵀr 的无穷范数小于阈值）。我实测：热启动解 travel=20/rack=5，nfev=4、耗时 5.82ms、残差 5.8e-12mm——4 次迭代、真实残差评估约 4+18×4=76 次。

(a) 如上：数值雅可比是默认 `jac='2-point'` 前向差分，每个 njev 隐藏 18 次评估；典型问题热启动 3~4 次迭代收敛，冷启动（build 后直接大步）也在十几次以内；单次 solve_pose 实测中位 **5.82ms**（30 次重复），一次完整 160mm 扫掠 146ms。 (b) xtol=1e-10 对毫米制变量的实际含义要按相对形式算：‖x‖~1e3mm 时步长阈值约 1e-10×1e3=1e-7mm，而双精度在 1e3 量级下的表示极限约 2e-16×1e3=2e-13mm——所以是"贴着但没越过"机器精度，还留了 3 个数量级余量。放宽到 1e-8 会把步长阈值放到 1e-5mm，对 K&C 输出角的影响在 1e-5 度级，我**没有系统实测过放宽后的提速**，理由是 solve_pose 不是性能瓶颈（146ms/全扫掠），而这个紧容差对下游指标层的有限差分求导（±2mm 中心差分算 MR）有利。若要做实时拖拽帧内重解，这是我第一个要重新标定的参数。 (c) gtol 的梯度判据确实隐含量纲偏好：Jᵀr 把所有行混在一个内积里，数值大的残差行主导梯度。机制层全是 mm，无偏袒问题；但同一套容差思路带到 compliance 层（N 与 N·mm 混合）时就是真问题——那在 36 题正面回答。

**32. [难度5] `solve_rocker` 是纯后处理：轮侧解完后，用 60 次二分法解摇臂转角 θ，bracket 搜索半径到 ±3.1 rad。为什么摇臂不进 18 维状态向量？这个"事后求解"的架构决策牺牲了什么？**

**34. [难度4] 衬套"6DOF 力平衡"：`compliance.py` 的外层残差是 6·nd 维，`r[6k:6k+6] = f_ext − bush_force(δ)`。但代码注释写明"S1：仅平移外载；旋转 DOF 无外部力矩"——`f_ext[3:] = 0`。请推导：旋转三行的残差等于什么？TRF 会把 δ_rot 解到哪？**

**回答**：**结论：旋转三行残差 = −(kR(δ_rot) + (coupled·δ)[3:] + preload[3:])；在 S1 默认参数（preload/coupled 旋转分量为零）下最优解就是 δ_rot=0——所谓"6DOF 力平衡"实际退化成"3 平移平衡 + 3 个恒为零的摆设行"，我认这个定性。** 推导：`_residual`（compliance.py:176-194）里 `f_ext = np.zeros(6); f_ext[:3] = bush_ext[n]`，旋转三分量外载恒 0。平衡方程 r[3k+3:6k+6] = 0 − bush_force(δ)[3:] = −(b._fR[i](δ[3+i]) + (coupled@δ)[3+i] + preload[3+i])。线性刚度下这就是 −(kR·δ_rot)，唯一零点是 δ_rot=0，且该行对 δ_rot 的导数为 −kR>0，解是稳定吸引的——TRF 会精确解到 0（实测零载荷工况 δ 全分量 <1e-6）。

(a) 如上，对。什么时候会有非零旋转外载：S2+ 载荷阶段——制动/驱动反扭矩经铰链传到衬套、悬架行程迫使 LCA 旋转在橡胶衬套里产生的扭转力矩、以及衬套耦合矩阵注入非零项之后。这些都还没有工况入口（bushing.py docstring 明确登记耦合/阻尼/旋转力矩属 S3+）。 (b) preload 的语义与偏置：`bush_force` 最后一行 `return f + preload`，即预紧力作为零位移抗力直接加在平衡方程右侧。平衡 r=0 给 δ = (f_ext − preload)/k；纯预紧（f_ext=0）时 **δ = −preload/k**——预紧 500N、k=2000N/mm 时衬套被顶偏 0.25mm。这符合"零位移时已有内力"的力学语义（预紧让衬套工作点偏移），但要说清楚：它同时意味着机构的名义设计位形不再是零位移位形，K&C 输出里会带这份系统偏置。 (c) 旋转 DOF 的反力矩由"机构铰链承担"这句话的真实含义是：力矩被理想几何约束 silently 吸收，**约束反力没有恢复路径**——铰链反力矩传不回车身锚点载荷，`corner_to_anchor_loads` 只有 3 分量力。这条传力路径在 S1 架构里不存在，需要在 S2 静力层补铰链反力/反力矩恢复项（本质是对约束雅可比转置乘拉格朗日乘子，而我的位置级最小二乘恰好可以在收敛点免费拿到这个乘子近似——这是少数让我庆幸没用黑盒的地方）。

**40. [难度4] 衬套刚度模型：`Curve` 支持 linear / table / spline（Pchip），表外用 `np.clip` 截断。请回答三个边界问题：**

**49. [难度3] 低速与数值防护：`speed < 0.8` 时轮胎力整体清零，`alpha_st = atan2(vwy, max(|vwx|, 0.5))`，RK2 后 `mid[3:] = clip(±90)`，总步数上限 60000。这四道防线各防什么病？**

**回答**：(a) speed<0.8 清零防的是 atan2 在近零速下的侧偏角爆炸（vwx→0 时 α→±90°），但代价是 **Fy 在 0.8m/s 处满值跳零**——起步/掉头工况（FSAE 耐久赛就有低速弯）侧向力突变，纯追踪驾驶员的横摆误差积分会来回荡，表现为低速段轨迹锯齿。更平滑的做法是速度衰减因子（如 Fy 乘 min(1, speed/0.8)²）而非硬门限，没做。 (b) **clip(±90) 混了单位**：`mid[3:]` 是 [vx, vy, r]，vx/vy 是 m/s、r 是 rad/s，一个 clip 全盖——r=90rad/s 相当于每秒 14 圈，这个上限对 r 形同虚设；对 vx/vy 是 324km/h 的荒谬上限。所以这个 clip 的真实功能只有一个：发散后防 NaN 传播。**首次触发就意味着模型已经崩了**，而它是静默的——不记 warning（isfinite 检查在 run 层只看最终态），应把 clip 触发事件记录为警告。这是我细节上的不诚实设计：用数字上无害的钳位掩盖语义上已发散的事实。 (c) dt=0.01、上限 60000 步 = 600s 仿真封顶；典型赛道仿真（sim_time 25~30s）跑 2500~3000 步、毫秒级完成（parity 测试整组含 node 子进程在秒级跑完）。`keep = max(1, n_steps//1500)` 降采样只影响 trace 回放密度不影响积分精度——n_steps=3000 时 keep=2，隔步记录，1~2Hz 的瞬态细节保得住；若真跑到 60000 步，keep=40 意味着 0.4s 一条记录，回放会漏掉瞬态事件（summary 的 max_ay 是每步累计的不受影响）。诚实的说法是：轨迹回放图在大 sim_time 下失真，物理指标不失真。

**50. [难度4] 准静态-瞬态混合的载荷链：每步 `wheel_loads` 用上一步的 `prev_ay/prev_ax` 查准静态载荷，roll/pitch 用一阶滞后（τ_roll=0.18s、τ_pitch=0.25s、pitch 增益 0.55、travel = γ(rad)·|y|·1000mm）。这四个魔法数+两个公式，各自的验证来源是什么？**
