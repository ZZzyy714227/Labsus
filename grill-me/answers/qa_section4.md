**91. [难度4] 求解性能与算法成本：机构求解用 SciPy `least_squares`(TRF)，K&C 用 "TRF + Anderson 加速兜底"。请给出：残差向量多少维、典型迭代次数、单次 K&C 扫掠 31 步在什么 CPU 上耗时多少？为什么 K&C 需要 Anderson 加速——TRF 本身慢在哪？**

- 追问 3：技术文档里说"C++ 能挤出的 5ms 优化不值生态易用性"——这条结论有没有被实测数字支撑过？

**91. 回答**

如实给数字与结构：机构层是两层——**内层机构投影**是闭式投影迭代（`mechanism/solver.py`，残差 = 杆长/几何约束的闭式形式，维数与约束数同阶：每侧拉杆/推杆杆长约束 + 转向横拉杆约束，个位数量级）；**TRF（SciPy least_squares）**用于联合收敛与 K&C 外层力平衡（`compliance.py`）。典型迭代次数：热启动后 TRF 个位数次（KIN_MAX_NFEV=200 是上限不是常态）；单点端到端 43.6ms（题 90，playwright 实测）。**31 步扫掠的精确耗时我没有实测档案，只能给 31×45ms≈1.4s 的上界推算，测试机是普通开发笔记本**——这题里唯一不硬的数字，我明说。

Anderson 加速为什么需要：K&C 外层是衬套力平衡不动点迭代（δ→solve_pose→力→新 δ），刚度耦合让朴素不动点收敛慢甚至振荡；TRF 每次调用要重做数值雅可比（内层投影是黑盒），单步贵。Anderson 用历史 3 步（ANDERSON_MEM=3）做混合外推（BETA=0.5），把外层迭代数压下来，且兜底保证（ANDERSON_TOL=1e-6、MAX_STEP=5mm 限步防振）。

**追问 1**：continuation = 上一步解作初值 + 双向推进（`2743d8a` "bidirectional continuation, anchored LS polish"），travel 从 0 向两侧扫、步长固定小步；失败回退 = 续延断点时触发 steering fallback（转向路径重新求根），再不行该点标记不可达而非静默插值——`11eb2d5` 修的"压缩侧不可达垃圾 MR"就是这类失败曾经被静默吞掉的教训。

**追问 2**：10 倍性能路线图按性价比排序：①**并行扫掠**——31 点彼此独立（热启动依赖可用分块），进程池 4–8 倍，半天工时，先做这个；②**numba/向量热点**——投影迭代内核向量化或 jit，2–3 倍，1–2 天，风险是 SciPy TRF 与 numba 混排的调试成本；③**C++ 扩展**——5–10 倍但 pybind 工具链 + 交叉平台编译的维护成本对单人项目不成比例，不选。JAX 有自动微分的好处但我的约束是闭式投影、不需要导数，引入纯增重。

**追问 3**：**没有实测支撑，这条是判断不是结论**——依据是"求解已 43ms、用户感知瓶颈在交互与渲染而非求解"的量级推理，但我没做过 C++ 原型对比（也没做过 numba 对比）。诚实处理：把这句话从"结论"降级为"基于量级的取舍倾向"，并且如果哪天真有实时扫掠需求，先用 numba 做个 benchmark 再下结论。

**94. [难度3] 错误处理与降级：`5693c1b` 修了一个 "422 for bushings on unmapped RCK_AX_B"——用户输入什么会触发引擎不可恢复错误？前端的错误兜底是 `3f9006b` 里那个 "stageTick 全体 try/catch + 无条件 rAF"，这是好实践还是掩盖 bug 的创可贴？**

**追问 1**：物理层验证现状：结构校验靠 Pydantic（点数/类型/单位），**退化几何的显式预检不完整**——目前主要靠求解器的不可达→状态机兜底，而不是求解前主动检查"三点共线/两点重合"。这是已知缺口：预检能把 200 次 nfev 的白烧省掉，并给出更友好的错误定位。不收敛时返回：显式 status + warnings 列表，不返回半成品数值。
