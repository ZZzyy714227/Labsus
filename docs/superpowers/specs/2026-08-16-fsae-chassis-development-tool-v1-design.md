# FSAE 底盘快速迭代开发工具：产品与 V1 完整设计

> 状态：设计基线
>
> 本文在参考 `double-wishbone-suspension.html`、现有项目代码和车辆工程学习笔记的基础上，重新审查产品定位，并明确 V1 的交付边界、已具备基础、尚未完成内容及后续路线。

---

## 1. 先质问：这到底是不是一个底盘分析工具？

### 1.1 不是因为有指标就叫底盘分析工具

一个程序即使显示了 Camber、Toe、Caster、KPI、Roll Center、Ride Frequency 和红黄绿灯，也不一定是底盘分析工具。

真正的底盘分析工具至少要能够回答：

1. 分析的对象是什么？
2. 当前采用了什么硬点和机构拓扑？
3. 当前处于什么明确工况？
4. 机构姿态是如何求出来的？
5. 轮胎定位和载荷如何从姿态得到？
6. 悬架部件的力如何从轮胎力传递出来？
7. 结果是否收敛、是否平衡、是否超出适用范围？
8. 这个方案与另一个方案相比到底改变了什么？

如果这些问题无法追溯，软件就只是“参数展示器”或“3D 交互演示器”。

### 1.2 我们的最终定位

经过审查，目标产品应明确为：

> **面向 FSAE 赛车底盘硬点快速迭代的整车准静态几何与轮边受力分析工具。**

因此，它是底盘分析工具，但不是以下工具：

- 不是完整整车 CAD/数字样车平台；
- 不是车架有限元工具；
- 不是空力设计工具；
- 不是完整轮胎试验/轮胎模型工具；
- 不是时域多体动力学软件；
- 不是自动替工程师做最终设计决策的黑盒优化器。

### 1.3 为什么它仍然是“底盘分析”

它的工程核心对象是底盘方案，核心输入是硬点和车辆工况，核心输出是：

```text
悬架姿态
→ 四轮定位
→ 接地点与转向轴几何
→ 载荷转移
→ 轮胎力利用
→ 悬架杆件和球铰受力
→ 方案间工程差异
```

这条链路覆盖了底盘开发中最重要的第一阶段：

```text
几何方案建立
→ 运动学验证
→ 准静态载荷验证
→ 部件受力验证
→ 快速迭代
```

所以产品不是单纯“悬架计算器”，而是：

> **以悬架几何为核心的整车底盘开发分析工具。**

## 2. 产品目标与非目标

### 2.1 目标

让 FSAE 设计者可以快速完成：

```text
修改硬点/底盘参数
→ 检查机构合法性
→ 观察轮跳与转向运动学
→ 叠加侧倾、制动、加速等准静态工况
→ 获取四轮载荷
→ 获取轮边杆件力和球铰反力
→ 对比多个底盘方案
→ 根据敏感性决定下一轮修改
```

“快速”包括三层含义：

- **计算快**：单点交互反馈快，扫掠可接受；
- **理解快**：图形、曲线和残差能直接说明问题；
- **迭代快**：方案复制、工况复用、A/B 对比和回退成本低。

### 2.2 非目标

V1 不做：

- 车架管件强度和焊接可制造性；
- 车身、空力、动力总成和电池；
- 完整动力传递和差速器内部模型；
- 轮胎非线性高保真模型；
- 衬套、摆臂和球头柔性；
- 制动盘反扭矩和轮胎回正力矩；
- 随机路面和时域瞬态动力学；
- 自动决定“唯一最佳硬点方案”。

这些内容可以进入后续版本，但不应稀释 V1 的底盘分析主线。

## 3. 核心产品对象：整车底盘方案

V1 的一级对象不是单个硬点，也不是单轴悬架，而是：

```text
ChassisDesign
```

一个方案包含：

```text
整车底盘方案
├── 坐标系与车辆基准
├── 前悬架硬点与拓扑
├── 后悬架硬点与拓扑
├── 左右独立硬点实例（可由镜像模板初始化）
├── 左右轮/轮胎参数
├── 前轮转向系统
├── 前后弹簧与减振器
├── 前后防倾杆
├── 轴距与前后轮距
├── 整车质量、轴荷和重心
├── 制动/驱动载荷分配参数
└── 方案名称、版本和变更记录
```

车架在 V1 中不是结构分析对象。悬架车身侧硬点仍然需要位于统一整车坐标系中，但车架只提供固定安装参考。

### 3.1 方案版本与分析结果分离

方案回答：

```text
设计了什么？
```

工况回答：

```text
在什么条件下分析？
```

结果回答：

```text
这个方案在这个工况下表现如何？
```

因此结果必须绑定：

```text
ChassisDesign version
+ AnalysisCase version
+ Solver state
```

不能让一个页面上的指标混合来自不同硬点版本、不同扫掠范围和不同工况。

## 4. 分析工况模型

V1 的工况对象为：

```text
AnalysisCase
├── 名称与说明
├── 关联底盘方案版本
├── 几何运动输入（V1 直接轮跳模式）
│   ├── 前左轮跳
│   ├── 前右轮跳
│   ├── 后左轮跳
│   ├── 后右轮跳
│   └── 齿条位移
├── 姿态派生标签（V1 不与轮跳同时作为独立输入）
│   ├── heave
│   ├── roll
│   └── pitch
├── 外部载荷输入
│   ├── ax
│   ├── ay
│   ├── az
│   ├── 制动分配
│   └── 驱动分配
├── 模型开关
│   ├── 是否启用防倾杆
│   ├── 是否计算轮边受力
│   └── 是否启用轮胎附着检查
└── 求解与结果状态
```

### 4.1 几何输入不是附属功能

V1 采用“直接轮跳输入模式”：四轮轮跳和齿条位移是独立驱动量，heave/roll/pitch 只是由四轮轮跳反推的姿态标签，不与四轮轮跳同时作为独立约束输入。V1 不根据弹簧、防倾杆和轮胎力反求车身平衡姿态；该闭环属于 V2。

轮跳和转向是底盘分析的基础几何自由度：

```text
四轮轮跳
+ 齿条位移
+ 左右差动轮跳
→ 当前悬架与转向节姿态
```

V1 至少支持：

- 单轮压缩/回弹；
- 双轮同向跳；
- 四轮 heave；
- 左右差动轮跳；
- 纯转向；
- 轮跳 + 转向；
- 左右差动轮跳 + 转向。

### 4.2 外部载荷输入

外部载荷是另一组输入：

```text
ax、ay、az
+ 制动/驱动比例
→ 四轮 Fx/Fy/Fz
```

几何输入与载荷输入可以组合，但必须在结果中明确区分：

```text
当前姿态由什么几何输入得到
当前轮胎力由什么载荷工况得到
```

### 4.3 V1 预置工况

V1 预置以下工况：

1. 静态设计位置；
2. 前左/前右单轮压缩与回弹；
3. 后左/后右单轮压缩与回弹；
4. 前轴双轮同向跳；
5. 后轴双轮同向跳；
6. 四轮 heave；
7. 四轮左右差动轮跳；
8. 纯转向；
9. 轮跳 + 转向；
10. 1.3g 纯侧向；
11. 1.2g 纯制动；
12. 1.0g 纯加速。

侧向 + 转向、侧向 + 制动、制动 + 转向等复杂组合需要在数据结构中预留，可作为 V1 后半段或 V2 的计算扩展。

## 5. 统一几何机构模型

### 5.1 左右侧建模原则

左右关系必须分成三件事：

```text
几何模板：可以镜像初始化
运动状态：左右必须独立求解
受力状态：通过整车/转向/防倾杆耦合，绝不直接镜像
```

`mirror_left()` 这样的工具只能用于从对称右侧模板生成左侧初始硬点。生成后，左右硬点是独立实体，可以独立编辑；左右轮跳、转向节姿态、轮胎载荷和杆件力必须各自求解。

只有在“硬点完全镜像、左右轮跳相同、无转向、无侧向不对称载荷”的对称基准工况下，左右结果才应满足镜像关系。这个关系用于回归验证，不是 V1 的通用计算捷径。

### 5.2 运动学层

运动学必须体现真实双叉臂机构：

```text
上摆臂：整体刚体绕两个车身内点定义的铰轴运动
下摆臂：整体刚体绕两个车身内点定义的铰轴运动
转向节：整体刚体
横拉杆：长度约束
推杆/拉杆：长度约束或明确的运动学连接
```

核心不变量：

- 车身固定硬点不漂移；
- 摆臂内部相对距离不变；
- 转向节内部相对距离不变；
- 刚性杆长度保持；
- 轮胎和轮毂随转向节保持刚体关系。

轮跳和转向最终必须能够作用在同一个统一机构状态中，不能未经验证就把：

```text
bump 解
→ steer 解
→ 后处理拼接
```

当作最终完整解。P1 误差门基于 16 个 front-right travel/rack 工况的实测结果，冻结 V1 采用 **SEQUENTIAL_PREVIEW_WITH_HIGH_ACCURACY_VALIDATION**：顺序 `bump → steer` 保留为生产预览和兼容路径，统一约束候选仅作为后台/按需高精度校验。顺序路径在全行程仍有原始残差超标（负行程最大约 0.731417 mm，正行程最大约 0.497062 mm；正常阈值为 0.02 mm）；候选路径仅 4/16 行为 `VALID`、12/16 行为 `APPROXIMATE`，且定位角/接地点差异并不稳定，暂不具备替换生产路径的证据。现有分支延续、回退扫描和平滑测试属于必须保留的兼容资产。K-4 仍开放：已知是 nominal travel 外的 branch-anchored polish 残差妥协，本轮未修复。详见 `docs/superpowers/specs/2026-08-20-p1-solver-gate-report.md`。

### 5.3 受力层

运动学与受力分层，但引用同一个已收敛姿态。左右受力不是镜像复制：整车车身平衡、四轮载荷转移、前后轴分配、转向齿条和防倾杆都会把左右侧连接起来。

典型侧向工况为：

```text
外侧轮 Fz 增大
内侧轮 Fz 减小
左右轮跳不同
防倾杆发生扭转
左右杆件/球铰力不同
```

四轮轮胎力先由整车层共同分配，再分别进入四个轮边静力平衡；最后进行整车合力、力矩和左右耦合残差检查。

运动学与受力分层，但引用同一个已收敛姿态：

```text
运动学层：刚体、铰链、距离约束
受力层：二力杆、球铰、静力平衡
```

二力杆按轴向拉压力处理：

- UCA 前后支杆；
- LCA 前后支杆；
- 推杆/拉杆；
- 横拉杆；
- 防倾杆连杆。

球铰输出三向反力，不传递独立纯力矩：

- 上球头；
- 下球头；
- 摆臂内侧支点；
- 推杆/拉杆端点；
- 横拉杆端点；
- 防倾杆连杆端点。

## 6. V1 定位角与悬架几何指标

V1 不把定位角当成孤立数字，而是建立以下关系：

```text
主销/转向轴
→ KPI、Caster
→ Scrub Radius、Mechanical Trail
→ 转向力矩、回正、Jacking
→ 转向时 Camber/Toe
→ 轮胎接地状态
```

### 6.1 Camber 外倾角

输出：

- Static Camber；
- Camber vs Wheel Travel；
- Camber Gain per Travel；
- Camber vs Steering；
- Steering Camber Gain；
- Camber under Roll；
- Camber under Pitch；
- Combined Camber。

必须区分两种增益：

```text
行程型：Δcamber / Δwheel travel
转向型：Δcamber / Δsteering angle
```

外倾目标不能简单写成“越负越好”。它需要与：

- 轮胎接地印迹；
- 侧倾工况；
- 制动/加速；
- 轮胎载荷；
- 轮胎温度或实测反馈；

共同评价。

### 6.2 Toe 前束

输出：

- Static Toe；
- Toe vs Wheel Travel；
- Bump Steer；
- Bump-in/Bump-out 方向；
- Toe vs Rack；
- Toe under Roll/Pitch；
- Combined Toe；
- 左右轮 Toe；
- 总前束与左右差。

### 6.3 Ackermann

同时显示：

- 实际内轮转角；
- 实际外轮转角；
- 理想几何 Ackermann；
- Ackermann 百分比；
- Ackermann deviation；
- 转向中心；
- Ackermann 随轮跳、转向和侧倾的变化。

理想关系可以作为参考：

```text
cot(δ_outer) - cot(δ_inner) = track / wheelbase
```

但不得用理想公式替代真实转向机构结果。

### 6.4 KPI / SAI 主销内倾角

定义：

```text
从正视图看，转向轴/主销轴与垂直方向的横向夹角。
```

双叉臂中：

```text
Steering Axis = 上球头中心到下球头中心的连线
```

输出：

- Static KPI/SAI；
- KPI vs Wheel Travel；
- KPI vs Steering；
- 主销轴线；
- 主销轴与地面交点；
- KPI 引起的 jacking 趋势；
- KPI 对转向时 Camber 的影响。

KPI 的工程因果链：

```text
KPI
→ 主销轴地面交点横向移动
→ Scrub Radius 改变
→ Fx/Fy 作用下的绕转向轴力矩改变
→ 制动跑偏/扭矩转向趋势改变
→ 转向手感改变
→ 转向时 Camber 改变
→ 可能产生 jacking
```

### 6.5 Caster 主销后倾角

定义：

```text
从侧视图看，转向轴与垂直方向的纵向夹角。
```

输出：

- Static Caster；
- Caster vs Wheel Travel；
- Caster vs Steering；
- 主销接地点；
- Mechanical Trail；
- Caster 引起的 Steering Camber Gain；
- Caster 改变后的 Bump Steer。

Caster 不能与 Toe、Camber 分开静态解释：

```text
Caster
→ Trail 和自回正
→ 转向节绕斜转向轴运动
→ 转向 Camber Gain
→ 转向臂空间姿态改变
→ Bump Steer 改变
```

### 6.6 Scrub Radius

V1 统一使用距离定义，单位为 mm：

```text
主销轴与地面的交点
↔
轮胎接地印迹中心
```

输出：

- 正/零/负 Scrub；
- Scrub vs Wheel Travel；
- Scrub vs Steering；
- 左右差；
- Fx/Fy 作用下的几何转向力矩趋势。

第一版不加入制动盘反扭矩，但不能因此省略接地点力臂产生的力矩。

### 6.7 Included Angle

输出：

```text
Included Angle = Camber + KPI
```

具体符号必须服从统一坐标和角度约定。

### 6.8 Motion Ratio

从真实几何变化计算：

```text
Motion Ratio = Damper Travel / Wheel Travel
```

输出：

- 前后轴运动比；
- 左右轮运动比；
- Motion Ratio 曲线；
- 压缩/回弹差异；
- 轮端弹簧刚度；
- 减振器行程和超程警告。

不能在结果层用固定 `0.7`、`0.6` 等默认值伪装成当前几何的精确运动比。

## 7. V1 高级几何指标

### 7.1 Instant Center

分别分析：

- 正视 IC；
- 侧视 IC；
- IC 坐标；
- IC 随轮跳变化；
- 等效摆臂长度；
- IC 远离工作区或接近无穷的警告。

### 7.2 Roll Center

由当前摆臂方向、瞬时中心和接地点构造：

```text
IC
→ 接地点到 IC 的连线
→ 车辆中心线交点
→ 几何 Roll Center
```

输出：

- 前轴 Roll Center；
- 后轴 Roll Center；
- 高度和横向位置；
- Roll Center vs Wheel Travel；
- 左右不对称情况下的变化。

必须区分：

```text
几何 Roll Center
≠
完整时域动力学中的瞬时车身侧倾中心
```

### 7.3 Pitch Center、Anti-dive、Anti-squat

V1 计算：

- 侧视瞬时中心；
- 纵向几何中心/等效纵倾几何；
- Anti-dive；
- Anti-squat；
- Anti-lift。

结果必须标明这是几何比例，不等同于完整动态响应。

### 7.4 Jacking

在侧向工况中输出：

- 接地点到 RC 的连线角度；
- 几何力垂向分量；
- Jacking Force；
- Jacking percentage；
- RC 过高警告；
- 可能的内侧轮载荷异常。

### 7.5 车轮轨迹

V1 不只画轮心轨迹，还应计算：

- Wheel center X/Y/Z；
- Wheelbase change；
- Track change；
- Contact patch X/Y/Z；
- 主销接地点轨迹；
- 轮胎方向轴轨迹。

## 8. V1 整车准静态载荷与轮胎模型

### 8.1 整车层分配四轮载荷

V1 的纯侧向、纯制动和纯加速载荷工况默认使用“设计姿态/用户指定轮跳姿态”计算，不反求车身 roll、pitch 或 heave 平衡。结果因此是载荷与几何状态的准静态组合，不宣称已经完成弹簧、防倾杆、轮胎和车身姿态的闭环平衡；该闭环属于 V2。

`az` 在 V1 中表示相对设计基准的额外垂向加速度输入，默认值为 0；重力基准已包含在静态垂向载荷中，不重复叠加。

输入：

- 整车质量；
- 前后轴荷比例；
- 轴距；
- 前后轮距；
- CG 高度与纵向位置；
- `ax`、`ay`、`az`；
- 制动和驱动分配。

输出每个车轮：

```text
Fx、Fy、Fz
```

并输出：

- 前后轴垂向载荷；
- 左右轮垂向载荷；
- 纵向载荷转移；
- 横向载荷转移；
- 四轮合力残差；
- 整车力矩残差；
- 负载/离地警告。

### 8.2 载荷转移路径

V1 明确区分：

```text
总载荷转移
几何载荷转移
弹性载荷转移
非簧载质量载荷转移
```

基础趋势：

```text
横向总载荷转移 ∝ m · ay · hCG / track
纵向总载荷转移 ∝ m · ax · hCG / wheelbase
```

总量由整车物理参数决定，悬架主要调整：

- 前后分配；
- 几何/弹性路径；
- 转移发生时机；
- 侧倾和顶升代价。

### 8.3 轮胎附着检查

V1 使用简化附着边界：

```text
F_available = μ(Fz) · Fz
Fx² + Fy² ≤ F_available²
```

输出：

```text
Friction Utilization = sqrt(Fx² + Fy²) / F_available
```

标记：

- 附着余量充足；
- 接近极限；
- 超出简化摩擦圆。

V1 不声称已经具备完整 Pacejka 轮胎模型。

## 9. V1 轮边静力受力模型

### 9.1 输入

轮边只接收接地点三向力：

```text
Fx、Fy、Fz
```

暂不加入：

- 制动盘反扭矩；
- 轮胎回正力矩；
- 气压拖距；
- 轮毂轴承力矩；
- 结构柔性力矩。

### 9.2 结构理想化

二力杆输出轴向拉压力：

```text
F = λ · unit(P2 - P1)
```

球铰输出三向反力，不输出独立纯力矩。

### 9.3 每个轮边的输出

- UCA 前/后支杆轴向力；
- LCA 前/后支杆轴向力；
- 上球头三向反力；
- 下球头三向反力；
- 推杆/拉杆轴向力；
- 横拉杆轴向力；
- 稳定杆连杆轴向力；
- 摆臂内侧支点反力；
- 转向节合力残差；
- 转向节力矩残差；
- 摆臂力/力矩平衡残差；
- 拉压状态和最大部件载荷。

几何层保持真实双叉臂刚体/铰链关系，受力层才把支杆理想化为二力杆。这两个层次不能混为一谈。

## 10. 结果可信度与工程证据链

每个结果必须带有状态：

```text
VALID
APPROXIMATE
NOT_APPLICABLE
NOT_IMPLEMENTED
SOLVER_FAILED
EQUILIBRIUM_FAILED
OUT_OF_RANGE
```

必须同时显示：

- 受力合力残差；
- 受力力矩残差；
- 机构是否可达；
- 是否存在多解/分支风险；
- 是否使用简化轮胎模型；
- 是否使用简化载荷分配；
- 是否有默认/估算运动比；
- 是否存在轮胎负载不足；
- 是否超过摩擦圆；
- 是否超出杆件或减振器行程。

工程结果必须遵循：

```text
输入
→ 工况
→ 当前几何状态
→ 方程/假设
→ 求解结果
→ 残差
→ 适用范围
→ 工程解释
```

未实现的结果不得用空白、默认值或伪精确数值隐藏。

## 11. 数据模型迁移方案

### 11.1 服务端作为方案真源

V1 不再把 `DEFAULT_HARDPOINTS` 和 `hardpoint_overrides.json` 作为完整方案模型。服务端建立版本化 JSON 存储作为方案真源；V1 暂不引入 SQLite，避免在核心模型尚未稳定前增加数据库迁移成本。

建议结构：

```text
DataStore
├── chassis_designs/{design_id}.json
├── analysis_cases/{case_id}.json
└── analysis_results/{result_id}.json
```

`ChassisDesign` 保存设计输入，`AnalysisCase` 保存工况输入，`AnalysisResult` 保存不可变的方案版本/工况版本引用、求解摘要、曲线和状态。

### 11.2 旧数据兼容

- 现有 `DESIGN_PARAMS` 和硬点覆盖文件作为导入源；
- 启动时可生成一个 `legacy-import` 底盘方案；
- 旧 `/api/solve`、`/api/sweep` 暂保留兼容包装，内部转换为方案/工况输入；
- 旧 `mirror_left()` 只保留为几何模板初始化工具；不得用于生成受力结果、左右载荷或左右动态状态；
- 新分析 API 只接受明确的 `design_id/version` 和 `case_id`；
- 前端 localStorage 快照只作为迁移前历史读取源，不与正式方案版本并存为第二套真源；
- 迁移完成后，快照保存方案版本和工况版本，而不是保存一组无上下文页面状态。

### 11.3 API 迁移原则

先新增版本化 API，再迁移前端调用，最后标记旧接口兼容期。不得在同一个接口中混合“全局当前硬点”和“请求内方案硬点”。

## 12. 坐标、符号与角度规范

规范必须先于指标开发，并由单独的测试固定：

```text
X：车辆前方
Y：车辆左/右方向，正方向在方案元数据中声明
Z：垂直向上
```

实际左右和正方向必须在 `CoordinateConvention` 中显式记录；禁止依赖 `fix_left_angles`、`toe < 90°` 等后处理特判作为规范。

统一定义：

- Camber：从前视图定义，胎顶向外为正或负必须固定并写入元数据；
- Toe：从俯视图定义，Toe-in/Toe-out 与正负号固定；
- KPI/SAI：正视图转向轴与垂直线夹角；
- Caster：侧视图转向轴与垂直线夹角；
- Scrub Radius：主销轴地面交点到接地印迹中心的横向距离，单位 mm；
- Mechanical Trail：主销轴地面交点与接地印迹中心的纵向距离，单位 mm；
- Ackermann：明确内轮/外轮、左转/右转和百分比基准；
- Camber Gain：分别标注按轮跳和按转向角的导数。

规范完成后，必须重新核对左右镜像、角度符号、接地点和曲线导数测试。

## 13. 验证基准、性能预算与阈值

### 13.1 验证层级

1. 向量、旋转、投影和角度单元测试；
2. 手算硬点 benchmark：静态定位、主销、接地点、Scrub、Trail；
3. 刚性不变量测试：杆长、刚体内部距离、固定点；
4. 顺序 bump→steer 与候选统一约束解对照；
5. 前后轴、左右镜像和极端轮跳回归；
6. 与仓库 `ref/OptimumKinematics - Help File.pdf` 中可复现示例进行概念和数值对照；
7. 以后有实车数据时进行温度、定位和载荷趋势验证。

参考软件和实测用于校验，不被当作不可质疑的真值；所有差异必须记录模型假设。

### 13.2 初始验收阈值

阈值先作为 V1 基线，经过 benchmark 后允许按单位和尺度调整：

- 几何刚性长度残差：正常状态 ≤ 0.02 mm；
- 几何警告状态：> 0.02 mm，求解失败/不可达必须单独标记；
- 单轮静力合力残差：≤ 1 N 或外载荷的 0.1%，取较宽者；
- 单轮静力矩残差：≤ 1 N·mm 或外载荷力矩的 0.1%，取较宽者；
- 曲线不得出现未经解释的孤立跳变；跳变检测必须回到原始求解状态，禁止只靠后处理掩盖；
- 左右完全镜像输入的对应结果差异：角度 ≤ 1e-6 deg、长度 ≤ 1e-6 mm（浮点容差内）。

### 13.3 性能预算

- 单轴单点运动学：目标 < 50 ms；
- 四轮单点几何工况：目标 < 150 ms；
- 25–51 点单轴扫掠：目标 < 1 s；
- 基础四轮工况集分析：目标 < 3 s；
- A/B 对比不得重复计算完全相同的方案/工况哈希。

如果统一求解达不到预算，先保留顺序解作为交互预览，并在后台运行高精度验证，不牺牲结果状态透明度。

## 18. V1 验收流程

V1 不是用“界面有多少指标”验收，而是用以下完整工程流程验收：

```text
建立底盘方案 A
→ 编辑前后悬架硬点
→ 检查硬点和机构合法性
→ 做前后轴轮跳扫掠
→ 查看 Camber / Toe / Caster / KPI / Scrub / Trail
→ 查看 IC / RC / Pitch 几何 / MR / 轮心与接地点轨迹
→ 加入齿条位移，查看内外轮转角和 Ackermann
→ 运行轮跳 + 转向组合
→ 运行 1.3g 侧向、1.2g 制动、1.0g 加速
→ 得到四轮 Fx/Fy/Fz
→ 检查载荷转移和摩擦圆利用率
→ 得到每个轮边二力杆和球铰反力
→ 检查几何、力、力矩残差
→ 保存为方案 B
→ 在相同工况下比较 A/B
→ 输出硬点变化、指标变化、受力变化和警告
→ 判断下一轮硬点修改方向
```

必须能够明确回答：

```text
改了哪个点？
改变了什么几何？
影响了哪些定位角？
影响了哪些接地点和载荷？
影响了哪些杆件力？
付出了什么代价？
结果是否收敛和闭合？
```

---

## 19. 最终结论

再次质问后，结论是：

> **是的，这应该是一个底盘分析工具；但它必须是“面向 FSAE 快速迭代的底盘开发分析工具”，而不是指标展示器、整车模型展示器或单轴悬架动画。**

它的核心不是：

```text
显示更多角度
```

而是：

```text
同一个底盘方案
+ 同一个明确工况
+ 同一个统一几何状态
→ 可追溯的定位、接地、载荷和受力结果
→ 可比较的下一轮设计决策
```

V1 的最小正确产品闭环是：

```text
硬点
→ 统一四轮机构姿态
→ Camber / Toe / KPI / Caster
→ Scrub / Trail / RC / Pitch 几何
→ 四轮 Fx/Fy/Fz
→ 轮胎附着检查
→ 二力杆与球铰受力
→ 残差与可信状态
→ 方案 A/B 对比
```

这条链路成立，软件才真正完成了从“悬架可视化程序”到“FSAE 底盘快速迭代分析工具”的转变。
