# DWB-SIM 完整系统设计解析

> 分析对象：`double-wishbone-suspension.html`
>
> 本文只复原和解释原文件的设计、实现逻辑、正确性依据与局限，不提出迁移建议、不设计融合架构、不修改现有求解器。

## 1. 文档定位与阅读方法

DWB-SIM 是一个单 HTML 文件实现的双叉臂悬架运动学/动力学仿真台。它把设计硬点、机构拓扑、几何约束、弹性元件、动力学积分、运动学指标、Canvas 绘图和交互界面放在同一个运行时状态中。

它的核心思想不是通过经验公式直接计算“轮跳对应的外倾角”，而是：

```text
硬点定义
→ 机构拓扑
→ 刚性/弹性约束
→ 当前姿态求解
→ 几何指标计算
→ 图形和读数呈现
```

因此，文件既是一个可视化工具，也是一个小型的实时机构求解器和实验工作台。

文中“正确”分为两种含义：

- **几何约束正确**：杆长、铰链、刚体内部距离等不变量被满足；
- **工程模型正确**：坐标约定、力学假设、指标定义和单位符合目标车辆的实际含义。

原文件对第一类正确性投入较多，对第二类则采用了大量简化，因此两者需要分开阅读。

## 3. 设计数据与参数模型

### 3.1 硬点是设计输入的中心

硬点定义表 `HPDEF` 给每个点提供：

- ID；
- 中文和英文名称；
- 所属组件；
- 是否车身固定；
- 集中质量。

代表性定义包括：

```js
["LCA_F", "下摆臂前铰点", "chassis", 1, 0]
["LBJ",   "下球头",       "lca",     0, 2.0]
["UBJ",   "上球头",       "uca",     0, 1.5]
["WC",    "轮心",         "knuckle", 0, 10.4]
["TRO",   "横拉杆外点",   "knuckle", 0, 0.9]
["RACK",  "横拉杆内点",   "chassis", 1, 0]
```

实际坐标存放在 `S.hp`，使用三维数组表示。设计预设 `PRESETS` 同时保存硬点、轮胎、初始定位角、质量和刚度等参数。

这种组织方式使硬点成为系统的几何源数据：机构长度、轮胎姿态、主销线、轨迹和显示几何都从它派生。

### 3.2 固定节点与自由节点

`buildMech()` 将硬点转换为节点对象：

- `p`：当前坐标；
- `p0`：设计初始坐标；
- `pp`：上一积分位置；
- `v`：速度；
- `m`：质量；
- `w`：逆质量；
- `fix`：是否固定。

车身侧点的逆质量为 0，因此距离投影时不会被移动；运动件有有限逆质量，可以被约束修正。固定节点和自由节点在界面中分别用方形和圆形表示。

### 3.3 刚性线与可形变线

`LINKDEF` 使用 `[起点, 终点, 类型, 中文名, 分组]` 描述连接关系：

- `R`：刚性线，长度约束保持不变；
- `E`：可形变线，主要用于弹簧/减振器等力元件。

构建时每根线的初始长度由当前硬点自动计算：

```js
L0: dst(n[a].p, n[b].p)
```

横拉杆的 `L0` 再叠加 `tieTrim`，以表达前束调整。

这里的关键不是线条本身，而是线条同时承担三种角色：机构拓扑、几何约束清单和可视化图元来源。

## 4. 机构拓扑与刚体分组

### 4.1 下摆臂与上摆臂

下摆臂由两个车身侧铰点定义转轴，外部成员为 `LBJ` 和 `SPR_L`：

```js
hinge("LCA", "下摆臂", "LCA_F", "LCA_R", ["LBJ", "SPR_L"])
```

上摆臂由 `UCA_F`、`UCA_R` 定义转轴，成员为 `UBJ`：

```js
hinge("UCA", "上摆臂", "UCA_F", "UCA_R", ["UBJ"])
```

摆臂的内部相对坐标在设计位置保存为 `rel`。求解时不是逐根杆分别拉伸，而是让整个摆臂成员绕同一根真实铰轴旋转。

### 4.2 转向节整体刚体

转向节簇包括：

```js
["LBJ", "UBJ", "WC", "TRO"]
```

它们的相对位置被保存为相对于质量中心的 `rel`。当前状态下，程序寻找一个质量加权最佳刚体变换，将这组点整体移动和旋转。

这保证轮心、上下球头和横拉杆外点不会各自独立漂移。

### 4.3 稳定杆与弹性元件不属于同一刚体求解

稳定杆通过 `arbGeom()` 根据下摆臂位置解析构造；弹簧/减振器作为一条可形变线，主要在动力学模式中产生力。它们与摆臂和转向节之间通过端点位置联系，而不是加入同一个刚体簇。

## 5. 几何约束体系

### 5.1 距离约束

`projLink()` 对刚性线进行质量加权距离投影。设当前两点距离为 `d`，目标长度为 `L0`，约束误差为：

```text
C = d - L0
```

沿两点连线方向按逆质量分配修正量。固定节点逆质量为零，因此车身硬点不会被投影移动。函数返回当前这根线的绝对长度误差。

### 5.2 铰链约束

`projHinge()` 先取两个固定铰点的连线作为转轴，再对摆臂成员求一个最优单参数旋转角 `th`。角度来自当前成员位置与设计相对位置之间的加权投影：

```js
th = atan2(sn, cs)
```

随后将每个成员点绕轴旋转到新的位置。该操作直接保持：

- 外点到铰轴的轴向/径向关系；
- 摆臂成员之间的相对距离；
- 摆臂只能绕指定轴运动。

### 5.3 自由刚体约束

`projBody()` 用当前点集和初始相对点集建立协方差矩阵 `A`，调用 `polarQ()` 提取最接近的旋转。旋转由四元数维护，再转换为 3×3 矩阵放置所有成员点。

`polarQ()` 使用 Müller 风格的迭代修正，并以当前四元数热启动。这样可以减少姿态连续运动中的跳变，并避免直接使用容易产生数值问题的通用矩阵分解。

### 5.4 驱动约束

轮跳运动学模式中，驱动变量是轮心高度：

```js
M.n[M.i.WC].p[2] = drvZ
```

它不是一根普通杆，而是外部指定的几何边界条件。之后各类约束投影交替工作，使整个机构寻找满足轮心高度的姿态。

## 6. 几何求解流程

### 6.1 一次投影扫描

`sweepProj()` 的顺序是：

```text
设置轮心 Z
→ 投影横拉杆
→ 投影下摆臂
→ 投影上摆臂
→ 投影转向节刚体
```

这是一个约束顺序固定的 Gauss-Seidel 风格扫描。后面的投影会改变前面约束的误差，因此需要重复扫描。

### 6.2 迭代收敛

`solveKin()` 默认最多 260 次迭代，每 4 次扫描检查一次残差。残差是所有刚性线长度误差和轮心驱动误差中的最大值：

```js
M.res = residual(M, drvZ)
M.ok = res < 0.02
```

界面同时显示残差、迭代次数和求解耗时，因此用户能看到当前几何是否真正收敛，而不是只看动画。

### 6.3 Continuation 分步逼近

`driveTo()` 不让机构从当前位置一次跳到远处目标，而是按最大约 6 mm 的步长分段逼近。每个中间位置都以前一个位置作为热启动。

该策略的作用是保持连续物理分支，降低：

- 摆臂翻转；
- 刚体姿态跳变；
- 多解机构进入另一分支；
- 大跨度输入导致迭代发散。

### 6.4 行程极限扫描

`findLimits()` 从设计轮心高度开始，以 2 mm 步进向上、向下驱动。一旦残差超过约 0.03 mm，就停止该方向扫描。得到的几何极限再与缓冲块行程相交，形成实际工作范围。

因此工作行程同时受：

- 机构几何可达性；
- 压缩缓冲块；
- 复原限位块；

三者限制。

## 7. 运动学指标计算

`metrics()` 只使用当前求解姿态重新计算指标，而不是从输入轮跳直接套用固定曲线。

### 7.1 车轮轴、外倾与前束

设计状态中的轮面轴保存在 `axL`，当前转向节旋转矩阵将它变换到全局坐标：

```js
ax = nrm(mApply(R, M.axL))
```

由轴向量的 Z 分量得到外倾角，由 X-Y 平面方向得到前束角：

```js
cam = -asin(ax[2])
toe = atan2(ax[1], ax[0])
```

### 7.2 接地点

程序将竖直方向投影到轮面平面，得到轮胎面内的向下方向，再从轮心沿该方向减去轮胎半径，得到接地点 `cp`。

这使接地点会随外倾角和轮心姿态变化，而不是始终简单取轮心正下方。

### 7.3 主销、偏移距和拖距

上下球头连线是主销轴。程序根据其在不同坐标平面中的分量计算：

- 主销内倾角 KPI/SAI；
- 主销后倾角 CASTER。

再将主销线与接地平面相交，得到主销接地点 `kg`，并以接地点与 `kg` 的差计算擦地距和机械拖距。

### 7.4 瞬时中心和侧倾中心

摆臂内侧铰轴先与轮心所在横向平面相交，形成正视图中的等效铰点。下摆臂方向线和上摆臂方向线的交点是正视瞬心 `IC`。

接地点与瞬心的连线再与中心线相交，形成单侧侧倾中心。左右两侧存在时，程序进一步求两侧接地点到各自瞬心的连线交点，得到双侧侧倾中心。

### 7.5 速比和曲线导数

扫掠过程中保存弹簧长度、外倾角、前束、稳定杆角度等数据。相邻采样点差分得到：

- 运动速比；
- 外倾增益；
- 跳动转向；
- 稳定杆运动速比。

例如外倾增益和跳动转向按相邻样本差分，再归一化到每 25 mm 行程。

## 8. 弹簧、减振器与轮胎模型

### 8.1 弹簧力

动力学模式中，弹簧力由设计长度、当前长度、刚度和静态预载组成：

```text
F_s = F_0 + k_s (L_0 - L)
```

程序将负的拉伸弹簧力截断为零，因此该模型表现为只受压的弹簧。

### 8.2 压缩/回弹阻尼

根据弹簧两端相对速度沿弹簧轴线的投影，压缩和回弹采用不同阻尼系数：

```text
F_c = -c_b * relative_velocity  （压缩）
F_c = -c_r * relative_velocity  （回弹）
```

这体现了单向不同阻尼设定。

### 8.3 轮胎垂向刚度

路面高度高于接地点时，产生轮胎压缩量 `pen`：

```text
pen = road_height - contact_point_z
```

轮胎法向力为线性刚度加阻尼，并限制为非负。该力作用在轮心节点的 Z 方向。

### 8.4 缓冲块与复原限位

轮心行程超过上限或下限后，使用二次形式的等效力：

```text
F ∝ x²
```

这让限位块在接触初期柔和、继续压入后快速增硬。

## 9. 台架动力学与时间积分

动力学由 `stepDyn()` 实现。每个外部时间步再细分为 10 个子步，以提高弹簧、轮胎和约束同时存在时的稳定性。

每个子步的顺序为：

```text
设置车身侧位置
→ 计算路面位置和速度
→ 清零节点力并施加重力
→ 计算弹簧力和阻尼力
→ 计算缓冲块力
→ 根据接触状态计算轮胎力
→ 半隐式更新速度
→ 更新位置
→ 重复约束投影
→ 由位置差回写速度
```

节点速度先受力积分，再推进位置。随后执行 12 次几何投影，最后用投影后的位移差重新计算速度，避免投影改变位置后速度仍保留不一致状态。

该实现是实时台架动力学近似，不是完整多体动力学系统。质量集中在节点上，重力主要作用于自由节点，弹簧和轮胎力被简化为沿局部方向或垂向的等效力。

## 10. 横向稳定杆模型

### 10.1 几何

`arbGeom()` 将稳定杆连接点定义为下摆臂两点之间的比例位置：

```js
P0 = lerp(LCA_F, LBJ, t)
```

稳定杆臂上端位于固定的横向、纵向和垂向偏置位置。连杆长度在设计位置计算并保持不变。当前摆臂位置变化后，程序在一个几何平面内解析求出稳定杆臂角度 `psi`。

如果反余弦参数超出 [-1, 1]，则标记连杆超程。

### 10.2 扭转刚度

`arbRate()` 使用圆实心扭杆的极惯性矩：

```text
J = π d⁴ / 32
```

再按剪切模量、扭杆长度和力臂换算为轮心等效刚度。由于直径以四次方进入，稳定杆直径对刚度非常敏感。

### 10.3 侧倾刚度读数

界面将弹簧侧倾刚度和稳定杆侧倾刚度分别计算，再求轴总侧倾刚度和稳定杆占比。左右轮跳差用于估算稳定杆相对扭转角和连杆力。

## 11. 扫掠分析、缓存与曲线

`runSweep()` 在给定齿条位置和行程上下限内采样多个轮跳位置。每个采样点都重新求解机构并记录 `metrics()` 结果。

扫掠过程保存并恢复原状态，避免分析过程改变当前屏幕姿态。生成的 `rows` 是曲线和实时读数的共同数据源。

运动学模式显示：

- 外倾角—轮跳；
- 前束角—轮跳；
- 侧倾中心高—轮跳；
- 运动速比—轮跳；
- 主销偏移距—轮跳。

动力学模式则显示时间序列：

- 路面输入和轮跳；
- 轮胎垂向力；
- 弹簧力；
- 阻尼力；
- 外倾角随轮跳变化。

扫掠不会每一帧无条件重算。`dirtySweep` 和约 130 ms 的节流机制避免硬点、齿条或稳定杆参数修改时持续占用主线程。

## 12. 场景构建与绘图系统

### 12.1 数据驱动的场景图元

场景不是直接绘制到 Canvas，而是先构建统一图元数组：

- `l`：线段；
- `p`：折线/多边形，可填充；
- `n`：节点；
- `t`：文字。

辅助函数 `L3`、`PL`、`TX`、`ND` 只负责把世界坐标和样式写入场景数组。绘制层再统一投影、裁剪和渲染。

这种做法把“几何构造”和“屏幕绘制”分开：同一组场景数据可以进入四个视图。

### 12.2 机械部件的绘制

场景构建包括：

- 下摆臂和上摆臂的三角面片与支杆；
- 转向节半透明面片；
- 球头圆环；
- 轮胎侧壁、胎面、轮辋和辐条；
- 制动盘、轮毂、卡钳；
- 弹簧螺旋、减振器筒体和座；
- 横拉杆、齿条、转向臂；
- 主销轴线和主销接地点；
- 运动轨迹和主销扫掠；
- 稳定杆和连杆。

这些几何均以当前求解后的节点和指标为输入，因此绘图不会单独维护一套运动学位置。

### 12.3 四种视图

`VDEF` 定义：

- 正视图：X-Z；
- 俯视图：X-Y；
- 侧视图：Y-Z；
- 等轴测视图：三维透视。

正交视图用两个基向量投影，等轴测视图维护相机位置、前向、右向和上向向量。`fitView()` 根据当前节点和轮胎包围范围自动设置中心、比例尺、目标点和相机距离。

### 12.4 叠加分析图层

绘制层可叠加：

- 瞬心构造线；
- 侧倾中心；
- 主销偏移距和拖距尺寸；
- KPI、外倾、后倾角弧线；
- 转向中心和阿克曼线；
- 轨迹线；
- 力矢量；
- 坐标轴、比例尺和网格。

这些不是装饰，而是将求解器内部的几何对象直接暴露为可检查的视觉证据。

## 13. 用户界面与交互系统

### 13.1 工业风格布局

界面采用无圆角、无阴影、深色面板、等宽字体和明确颜色编码。主体为：

```text
左侧参数/控制面板
中间四视图工作区
右侧指标/曲线/求解器面板
底部状态栏
```

颜色语义固定：

- 青色：几何或运动学重点；
- 黄色：状态、瞬心、警告或高亮；
- 红色：固定节点、力、错误；
- 绿色：侧倾中心、正常状态；
- 紫色：轨迹或稳定杆。

### 13.2 参数输入

通用控件工厂包括滑块、数字输入框、选择框、按钮、复选项和只读读数。`UI.sync` 保存统一同步函数，使状态变化后控件显示与内部值保持一致，同时避免刷新正在编辑的输入框。

硬点表直接编辑 `S.hp`。正交视图中可以拖拽节点，拖拽结果同样写回 `S.hp`，然后重建机构和扫掠数据。

### 13.3 读数组织

右侧面板按领域分组：

- 车轮定位；
- 悬架运动学；
- 弹性元件与刚度；
- 侧倾刚度与稳定杆；
- 转向系统；
- 特性曲线；
- 模型与求解器状态。

这让瞬时几何结果、派生性能结果和求解健康状态同时可见。

### 13.4 交互方式

支持：

- 正交视图硬点拖拽；
- 等轴测旋转与平移；
- 鼠标滚轮缩放；
- 双击适应窗口；
- 单视图最大化；
- 键盘轮跳和齿条微调；
- 运行/暂停；
- 工况预设；
- 显示层开关。

拖拽硬点时可用 Shift 进行更细的 0.1 mm 步进，否则采用 1 mm 步进。

## 14. 状态管理与刷新机制

全局对象 `S` 保存设计和用户输入，`SIM` 保存机构实例、指标、扫掠、轨迹和脏标志，`UI` 保存界面临时状态。

主循环的基本顺序是：

```text
更新时间和激励
→ 按需更新扫掠缓存
→ simulate()
→ buildScene()
→ drawAll()
→ updateReadouts()
→ drawPlots()
→ UI.sync()
→ 更新 FPS
```

几何修改分为两种：

- `rebuild()`：完整重建左右机构、重新计算几何极限和派生数据；
- `rebuildLight()`：保留部分当前输入，重建机构并刷新派生数据。

`dirtyGeom` 和 `dirtySweep` 用于区分需要全量重算还是只需要更新曲线扫掠。

## 15. 几何正确性保障

### 15.1 初始长度来自同一组硬点

所有刚性线的目标长度都由同一设计位形直接测量，不存在“硬点一套、杆长另一套”的手工同步问题。

### 15.2 固定车身点不漂移

车身节点逆质量为 0，约束投影只能调整自由节点。齿条输入也只移动固定的 `RACK` 节点，并通过重新求解让横拉杆和转向节响应。

### 15.3 摆臂和转向节保持刚体结构

摆臂使用绕真实铰轴的整体旋转，转向节使用质量加权刚体变换。这样内部点不会因逐点约束误差而逐渐变形。

### 15.4 最大约束残差

每次运动学求解都检查所有刚性线长度误差，并把最大值显示在顶部状态栏、右侧模型面板和状态颜色中。代码将小于 0.02 mm 作为当前求解成功阈值，界面还区分更严格的正常、警告和错误区间。

### 15.5 连续分支跟踪

大跨度轮跳被拆成连续小步，动力学模式则每个子步从上一状态继续。这是防止机构跳到错误空间分支的主要机制。

### 15.6 几何工作范围扫描

程序用残差阈值扫描上下行程极限，并将几何极限与缓冲块/限位块共同作用到工作行程。

### 15.7 可视化验证

四视图、轨迹、主销扫掠、瞬心构造线、尺寸标注和节点坐标让用户可以直接观察：

- 摆臂是否绕正确轴运动；
- 转向节是否保持刚体；
- 轮心轨迹是否连续；
- 主销和接地点是否符合当前姿态；
- 左右侧镜像是否一致；
- 机构是否接近不可达位置。

## 16. 数值稳定性与异常情况

### 16.1 投影法的性质

交替投影速度快、适合实时交互，但不是一次性严格求解全部非线性方程。不同约束之间可能反复影响，因此需要迭代和残差检查。

### 16.2 可能的分支问题

当机构接近奇异位形、摆臂接近平行或约束方向退化时，可能出现：

- 瞬心远离工作区；
- 投影收敛变慢；
- 横拉杆无法满足长度；
- 刚体旋转进入另一分支；
- 运动学曲线出现异常斜率。

continuation 和四元数热启动可以降低风险，但不能消除机构本身的多解性和奇异性。

### 16.3 动力学稳定性

动力学采用子步、速度上限、位置投影和速度回写控制数值发散。它更偏向交互展示和趋势观察，不能单凭界面读数等同于高保真多体动力学结果。

### 16.4 坐标约定

文件注释和 UI 对坐标的描述强调 X 横向、Y 纵向、Z 垂向，正视/俯视/侧视投影也按此实现。阅读时应以实际投影向量、角度公式和绘图代码为准，而不能只依赖顶部注释中的文字描述。

### 16.5 单位与内部缩放

几何长度使用 mm，质量 kg，时间 s，力学内部通过 `FS=1000` 将 N 转换为适配 mm 的内部力单位。读数层再换算回 N、N/mm、Hz 等工程单位。单位换算分散在动力学、刚度和读数代码中，是理解结果时必须追踪的部分。

## 17. 代码组织与单文件架构

该文件没有采用模块化目录，但用编号分区和职责命名形成了“逻辑模块”：数学、数据、机构、求解、指标、动力学、仿真、绘图、UI、交互、主循环。

单文件带来的优点：

- 示例可以直接打开运行；
- 数据流短，调用链容易追踪；
- 适合快速改参数和实验；
- 不需要构建工具或后端。

单文件带来的限制：

- 状态、求解、绘图和 UI 共享大量全局对象；
- 模块边界靠约定而不是类型或文件系统保证；
- 单个函数修改可能影响多个层；
- 自动化测试和替换单个子系统相对困难。

## 18. 系统设计优点

1. **几何源头统一**：硬点是杆长、机构和显示的共同来源。
2. **机构关系显式**：刚性线、铰链簇、刚体簇和弹性线各有明确语义。
3. **求解与显示闭环**：图形直接使用当前求解位置，状态栏暴露残差。
4. **轮跳输入直观**：轮心高度驱动，容易观察因果关系。
5. **连续求解意识强**：分步逼近和热启动减少错误分支。
6. **运动学与动力学共用机构**：同一套节点和约束可切换准静态与台架模式。
7. **可视化具有诊断功能**：轨迹、瞬心、主销扫掠和尺寸不是单纯美化。
8. **参数可实验化**：预设、滑块、硬点表、扫掠曲线和优化按钮组成了快速试验台。
9. **求解健康可见**：节点数、自由度、残差、迭代次数和耗时直接呈现。

## 19. 系统设计局限

1. 交替投影是近似迭代，不等同于严格的全局非线性方程求解。
2. 仅显示最大刚性残差，不能完全代表所有工程正确性。
3. 部分自由度由连续热启动隐式确定，缺少显式分支选择器。
4. 轮胎、弹簧、阻尼、缓冲块和路面接触均为简化模型。
5. 动力学质量、力和约束处理不是完整的多体动力学和力矩平衡。
6. 左右侧主要采用镜像模型，不能表达完全不对称的真实硬点。
7. 坐标说明、符号约定和某些指标命名需要结合代码核对。
8. 曲线导数依赖有限采样，采样间隔会影响增益读数。
9. 视图绘制是线框和示意面片，视觉穿插不等于实体碰撞检测。
10. 单文件架构使长期维护、复用和自动验证的边界不够强。

## 20. 完整数据流总结

```text
预设 / 硬点表 / 滑块 / 拖拽
            ↓
             S：设计输入和运行参数
            ↓
       buildMech()：节点、线、刚体簇
            ↓
  refreshDerived()：几何极限、扫掠、预载、路面基准
            ↓
  simulate()：运动学 driveTo 或动力学 stepDyn
            ↓
       metrics()：当前几何指标
            ↓
 buildScene()：线、面、节点、轨迹、标注、力
            ↓
 drawAll() / drawPlots() / updateReadouts()
            ↓
     四视图、曲线、状态栏、指标面板
```

几何约束链是：

```text
轮心高度驱动
→ 横拉杆长度
→ 下摆臂绕内侧轴
→ 上摆臂绕内侧轴
→ 转向节整体刚体姿态
→ 轮胎轴、接地点、主销轴变化
→ 外倾、前束、瞬心、侧倾中心等结果
```

动力学链是在同一几何链上增加：

```text
重力 + 弹簧 + 阻尼 + 缓冲块 + 轮胎接触 + 路面输入
→ 速度/位置积分
→ 几何约束投影
→ 约束后速度回写
```

## 21. 术语表

| 术语 | 含义 |
|---|---|
| Hardpoint | 悬架机构中定义空间位置的设计硬点 |
| Fixed node | 车身侧固定节点，逆质量为零 |
| Free node | 可被约束投影和动力学积分移动的节点 |
| Rigid link | 长度保持不变的刚性连接 |
| Elastic link | 通过力而不是固定长度表达的可形变连接 |
| Hinge cluster | 绕固定铰轴转动的一组摆臂节点 |
| Free body cluster | 保持内部相对距离的整体刚体节点组 |
| Projection | 将当前状态修正到约束流形附近的几何操作 |
| Residual | 当前约束误差，本文中主要指最大长度误差 |
| Continuation | 通过连续小步逼近目标来保持解分支 |
| IC | Instant Centre，正视图或侧视图中的瞬时中心 |

| Bump steer | 轮跳引起的前束变化 |

## 22. 结论

DWB-SIM 的核心价值不在于单个公式或界面样式，而在于它把完整悬架工作台建立在一条连续的几何因果链上：

```text
设计硬点
→ 机构拓扑
→ 几何不变量
→ 当前姿态
→ 轮胎/主销空间方向
→ 运动学指标
→ 弹性和动力学响应
→ 可视化诊断
```

它用少量明确的几何原语——节点、刚性距离、铰链旋转、刚体变换和驱动约束——构成双叉臂机构；再把弹簧、减振器、轮胎、稳定杆和路面作为附加物理层叠加到同一机构状态上。界面和绘图系统则将这些内部对象暴露成可操作、可观察、可调试的仿真台。

本文到此止于对原系统的完整分析，不对其他系统作比较，也不包含迁移或融合方案。
