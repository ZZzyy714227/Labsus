# 快速迭代悬架设计工作台 — 设计文档

> 日期：2026-08-12 | 状态：已批准（brainstorming 完成）| 前端方案：重写（Neo-Brutalist）
> 关联：docs/DEVLOG.md（现状）、docs/FAULT_ANALYSIS_REPORT.md（F1-F6 故障）

## 1. 背景与目标

现有工具（FSAE 悬架运动学分析器）功能齐全但**面向"分析"而非"设计迭代"**。用户的核心目的是：

> 自由设计悬架几何 → 快速得到性能指标 → 快速调整 → 再看指标。

**目标**：把工具重构为**快速迭代设计工作台**——每次调整（秒级）都能看到指标反馈（目标带红绿灯），每次改动自动留痕（快照），可回退、可对比。所有设计决策服务"闭环速度"。

**成功标准**：
- 一轮"改参数 → 看指标 → 判断好坏"闭环 ≤ 2 秒（含重量指标）
- 拖动参数时运动学指标实时刷新（<100ms）
- 任意两步迭代可对比、可回退，零成本

## 2. 核心用户工作流

```
[拖动参数/3D] → 单点运动学实时跳（<100ms）
     ↓ 松手
[快速 sweep] → 范围类指标（bump steer、Δcamber 等）填充（<500ms）
     ↓ 展开指标盘 / 点分析
[/api/analyze] → 4 维全量指标 + 12+ 项目标带红绿灯（<2s）
     ↓ 每次调整动作结束
[自动快照] → 时间线记录（参数 + 指标摘要），可回退/对比
```

## 3. 非目标（YAGNI）

- 不做拓扑级自由（仅双叉臂 + 推杆/拉杆，几何参数自由）
- 不做多体动力学（平面侧倾模型足够 FSAE 迭代）
- 不做导出报告/数据（用户确认暂不需要）
- 管件 CRUD / 覆盖面 / 空力面板**首版不迁移**，后续加回
- 不做自动优化（optimize_fl1 保留但非首版重点）

## 4. UI 设计 — Neo-Brutalist 工作台

### 4.1 视觉规范

| 令牌 | 值 | 用途 |
|---|---|---|
| 主色 | `#000000` | 边框、主背景（顶栏/表头） |
| 辅色 | `#ffffff` | 页面背景、卡片背景 |
| 强调·青 | `#00d9ff` | 运动学维度 |
| 强调·橙 | `#ff9500` | 姿态侧倾维度 |
| 强调·粉 | `#ff006e` | 动力学维度 |
| 强调·荧光绿 | `#ccff00` | 结构受力维度 |
| 绿/黄/红 | `#00e676` / `#ffd600` / `#ff1744` | 目标带状态灯 |

- 全局：`border-radius: 0`、粗边框（2-4px 黑）、硬边缘阴影（`4px 4px 0 #000`）
- 维度 → 强调色映射是唯一的指标分组标识（配合图标，不依赖色觉）
- 无障碍：文字与背景对比度 ≥ 4.5:1；橙 `#ff9500` 仅用于大色块/加粗，不用小字

### 4.2 布局（推挤式，零遮挡）

三区推挤重排（flex），**任何面板都是布局的一部分，无 overlay 覆盖**：

| 模式 | 布局 |
|---|---|
| 默认（调参） | 左参数栏 22% + 3D 78% + 底部历史条 |
| 指标盘展开 | 左参数折叠为 34px 图标条 + 3D 38% + 指标盘 55% |

- 顶栏（黑底白字）：标题 + 达标汇总灯（如 `● 11/12`）+ 按钮（指标盘/回退/对比）
- 底部历史条：快照数据行时间线（见 §8），两种密度（数据行 / 紧凑圆点）
- 轮跳/转向滑块叠在 3D 下方（拖动时顶栏灯实时跳）

### 4.3 指标盘（右栏，55%）

- 4 维分组卡片（维度色左边条），每项一行：状态灯 + 名称 + 数值 + 目标带
- 每项点击 → 展开该指标曲线（目标带背景色带）
- 重指标未算完显示「计算中 ▓▓」防抖后刷新
- 对比模式：每项显示 旧值（划线）→ 新值 + Δ + 双灯；曲线灰虚线叠加

## 5. 指标体系（4 维）与目标带

### 5.1 目标带预置（FSAE 经验草案，可逐项修改）

**运动学**（前后轴独立）：
| 指标 | 绿 | 黄 | 红 |
|---|---|---|---|
| camber 变化（±30mm） | Δ<3.5° | 3.5–5° | >5° |
| camber 曲线形态 | bump 增负倾 | 平坦 | 反向 |
| bump steer（±25mm） | <1.0° | 1.0–2.0° | >2.0° |
| caster 变化 | <3.0° | 3–5° | >5° |
| KPI 变化 | <3.0° | 3–5° | >5° |
| scrub 变化 | <15mm | 15–25mm | >25mm |

**姿态侧倾**（依赖整车参数 + 防倾杆）：
| 指标 | 绿 | 黄 | 红 |
|---|---|---|---|
| roll gradient | 0.8–1.5°/g | 0.5–0.8 / 1.5–2.0 | 其他 |
| RC 高度（静态） | 20–60mm | 10–20 / 60–80 | 其他 |
| RC 高度变化（±30mm） | <30mm | 30–50mm | >50mm |
| anti-dive（1.2g 制动） | 20–40% | 10–20 / 40–60% | 其他 |
| anti-squat（加速） | 20–40% | 10–20 / 40–60% | 其他 |
| jacking（1.3g 侧向） | <5mm | 5–15mm | >15mm |

**动力学**（依赖弹簧/避震/防倾杆参数）：
| 指标 | 绿 | 黄 | 红 |
|---|---|---|---|
| ride freq 前 | 2.0–2.5Hz | 1.7–2.0 / 2.5–2.8 | 其他 |
| ride freq 后 | 2.5–3.0Hz | 2.2–2.5 / 3.0–3.3 | 其他 |
| 频率比 后/前 | 1.15–1.30 | 1.05–1.15 / 1.30–1.40 | 其他 |
| 阻尼比 | 0.5–0.9 | 0.3–0.5 / 0.9–1.1 | 其他 |
| MR 前 | 0.5–0.9 | 0.35–0.5 / 0.9–1.1 | 其他 |
| MR 后 | 0.4–1.0 | 0.25–0.4 / 1.0–1.2 | 其他 |
| 载荷转移前/后分配 | 45–55% | 40–45 / 55–60 | 其他 |

**结构受力**（工况 1.3g 侧向 / 1.2g 制动 / 1.0g 加速）：
| 指标 | 绿 | 黄 | 红 |
|---|---|---|---|
| 推杆力（最大工况） | <1500N | 1500–2500N | >2500N |
| UCA/LCA 力 | <800N | 800–1400N | >1400N |
| 转向拉杆力 | <300N | 300–600N | >600N |

### 5.2 轻量/重量指标分级

| 级别 | 触发 | 覆盖 | 预算 |
|---|---|---|---|
| 轻量·单点 | 拖动中（节流 100ms） | 当前姿态 camber/toe/caster/KPI 瞬时值（**不做红绿灯评估**，仅显示数值与趋势方向） | <100ms（复用 /api/solve） |
| 轻量·快速 sweep | 松手 | 范围类：bump steer、Δ 变化、MR、damper travel（这些才产生运动学维度红绿灯） | <500ms（新增，25 步 PBD only） |
| 重量·analyze | 展开指标盘 / 点分析 | 姿态 + 动力学 + 结构 + 全量红绿灯 | <2s |

## 6. 计算架构

### 6.1 复用（不重写）

- `src/solver/bump.py`、`steering.py`、`angles.py`、`rocker.py` — 运动学核心
- `/api/solve`、`/api/sweep`（精确版保留给未来验证用）、`/api/defaults`、硬点持久化

### 6.2 新增模块（`src/metrics/`）

| 模块 | 职责 | 关键计算 |
|---|---|---|
| `roll.py` | 姿态侧倾 | RC = UCA/LCA 延长线交点法（瞬时中心），随轮跳曲线；总侧倾刚度 = Σ(K·MR²) 弹簧 + K_arb·MR_arb² 防倾杆 → roll gradient；anti-dive/squat 推力线投影；jacking 侧倾升高 |
| `dynamics.py` | 动力学 | ride freq = 1/2π·√(K·MR²/m簧上)（前后）；阻尼比 = C·MR²/(2√(K·MR²·m))；载荷转移 ΔF = m·a_y·h/t，前后分配 |
| `loads.py` | 结构受力 | 3 工况静态力平衡：按硬点力臂逐杆求解 UCA/LCA/推杆/拉杆/转向杆力 |
| `targets.py` | 目标带 | 预置表 + 用户覆盖 → `evaluate(metrics) → lights{green/yellow/red}`，一套逻辑前后端共用 |

### 6.3 模型假设

1. 平面侧倾模型（heave + roll 两自由度），线性弹簧/阻尼，不做多体动力学
2. 结构力 = 静态力平衡，工况给定加速度，无动态惯性效应
3. 整车参数新增：质量/前后轴荷/重心高度/轮距轴距/前后弹簧刚度/前后避震阻尼/前后防倾杆刚度

### 6.4 性能约束（前置依赖）

现有 `/api/sweep`（121 步 + scipy polish）实测 60–90s，**不能进入迭代路径**。新增**快速 sweep**：25–31 步、PBD only、跳过 polish，预算 <500ms（预计 PBD 每步 ~10ms）。

**PBD 漂移问题（故障报告 F1）在 ±15mm 外显著，直接污染快速 sweep 的范围指标。因此实施顺序中必须先修复 F1/F2（3 个失败测试），再做指标层。**

## 7. API 设计

```
POST /api/analyze          # 全量：几何+整车参数 → {metrics: 4维, lights, curves}
POST /api/vehicle          # 保存整车参数（持久化）
POST /api/targets          # 保存目标带覆盖
GET  /api/defaults         # 扩展：返回 vehicle_params + targets
POST /api/sweep_fast       # 快速 sweep（25步 PBD only，运动学范围指标）
```

- analyze 结果按（几何 hash + 整车参数版本）缓存，未变不重算
- 目标带评估在后端（targets.py），前端只渲染 lights

## 8. 迭代历史机制

- **快照触发**：调整动作结束（松手/确认）后 1s 防抖；**几何参数或整车参数任一有变化**才记录，否则跳过
- **快照内容**：时间戳 + 几何参数 + 整车参数 + 当时全量红绿灯摘要（22 项）
- **存储**：前端 localStorage（~1KB/条），上限 100 条滚动淘汰
- **时间线**（底部）：快照数据行——每行：序号/时间/改动描述 + 5 项关键指标数值（相对上一行变好者灰色划线）+ 最差指标徽章 + 状态灯；可折叠为紧凑圆点模式
- **回退**：点节点 → 恢复几何+整车参数 → 重算
- **对比**：选两行 → 指标盘对比模式（旧值划线 → 新值 + Δ + 双灯 + 曲线叠加）

## 9. 数据模型与持久化

- `data/persistent_state.json` 扩展：`+ vehicle_params`、`+ target_bands`
- 前端 localStorage：`workbench.snapshots`（快照历史，上限 100）
- 目标带修改不产生快照（评判标准非设计），但持久化保存

## 10. 测试策略

- **单元**：metrics 各模块（RC 已知几何手算值、roll gradient 解析解、连杆力力平衡闭合验证、目标带边界值）
- **集成**：/api/analyze 端到端（FastAPI TestClient），几何不变结果缓存命中
- **回归**：现有 144 测试全保持绿色（含修复 F1/F2 后的 3 个失败测试）
- **E2E**：Playwright——拖动→指标更新→快照生成→回退→对比 全流程（修复 sweep 性能后启用）

## 11. 实施顺序（阶段）

1. **P0 求解器健康**：修 3 个失败测试（`test_ramp_of_three_consecutive_jumps` / `test_sweep_toe_curve_continuous` / `test_sweep_curves_are_smooth`）+ F4 接地点 + F6 颜色索引。快速 sweep 模式（PBD only 参数化现有 sweep）。
2. **P1 指标层**：`src/metrics/` 四模块 + `/api/analyze` + `/api/vehicle` + `/api/targets` + 目标带预置表，全量测试。
3. **P2 工作台前端**：Neo-Brutalist 工作台重写（Vite + 自定义 CSS），推挤式布局、指标盘、时间线、对比模式、快照引擎。
4. **P3 打磨**：曲线展开、快速 sweep 精度微调、无障碍核对。

## 12. 风险

- **PBD 漂移未根治则快速 sweep 失真** → P0 优先，且快速 sweep 曲线过 post-processor（`_remove_branch_jumps` 修复后版本）
- **前端重写范围失控** → 严格按 §3 非目标裁剪，管件/覆盖面/空力后续独立加回
- **analyze 超 2s** → 指标分级计算（先运动学后姿态/动力学），缓存 + 增量更新
