# FSAE 悬架分析软件 — 验证测试故障分析报告

## 概述

对 FSAE 悬架运动学分析软件进行了全面的验证测试，模拟了工程师在软件中进行的全部操作流程（79 个测试项），发现 **6 个确认故障** 和 **2 个设计缺陷**。

测试结果：68 通过 / 11 失败（其中 4 个失败为测试预期问题，其余为真实故障）。

## F1: PBD 求解器 UP1 沿 UCA 圆弧漂移（严重）

### 现象

在轮跳 ±25mm 范围内，后倾角和 KPI 发生剧烈变化，违反了双叉臂悬架的基本物理规律：

| 轮跳 (mm) | UP1.X (设计值=6.52) | 后倾角 (设计值=5.183°) | KPI (设计值=2.078°) | 主销长度 (设计值=112) |
|-----------|---------------------|------------------------|--------------------|--------------------|
| -25 | 1.70 | 3.679° | 3.789° | 110.31 |
| 0 | 6.52 | 5.183° | 2.078° | 112.00 |
| +25 | 19.44 | 12.934° | -0.446° | 111.99 |

后倾角变化 9.25°（应 <0.5°），KPI 变化 4.24°（应 <0.5°）。-25mm 时主销缩短 1.69mm，UCA 约束半径偏差 4.53mm。

### 根因

PBD 求解器 (`_solve_bump_pbd`) 的 Gauss-Seidel 约束求解顺序中，`enforce_distance_fixed_q(UP1, UP5)` 在执行后重新破坏了前一步 `closest_point_on_circle` 对 UCA 圆的投影结果。当 UCA 枢轴轴线接近水平（overrides 后 CH1.Z=CH2.Z=220）时，`closest_point_on_circle` 无法自纠正 X 方向漂移——轴线参数 t 只取决于 UP1.X/Y，与 Z 无关。

迭代过程中 UP1.X 从 6.52 漂移到 19.44（+25mm），后倾角每 mm 漂移变化约 0.51°。在回弹（-25mm）方向，PBD 无法收敛（80 次迭代后残差 4.53mm）。

### 影响范围

所有使用 PBD 求解器的操作都受影响：轮跳滑块拖动、运动学扫描、FL1 优化。尤其在 ±15mm 以上轮跳时偏差显著。

### 修复方向

1. 增加迭代次数或调整阻尼策略（如在约束间交替松弛）
2. 在 PBD 循环中增加 UP1-UP2 距离约束的权重
3. 改为同时求解所有约束的雅可比方法而非顺序投影
4. 使用设计位置作为锚点，限制 UP1/UP2 偏离设计位置的幅度

## F2: LS 精化门槛和边界问题导致曲线不连续（严重）

### 现象

运动学扫描曲线在 dz≈-16mm 处出现 0.65° 的外倾角跳变，在 dz≈-1mm 处出现 0.70° 的跳变。

### 根因

两层问题叠加：

**2a. 门槛条件 `abs(dz) <= 15.5`（bump.py 第209行）**：LS 精化仅在"正常范围"内启用，超出范围直接使用 PBD 结果。在门槛边界处：
- dz=-16（仅 PBD）：后倾角=3.543°，残差=2.44mm
- dz=-15（PBD+LS）：后倾角=6.158°，残差=2.07mm
- 跨 1mm 轮跳，后倾角跳变 2.615°

**2b. LS 边界过窄（±5mm，bump.py 第211-213行）**：LS 以 PBD 结果为起点，边界 ±5mm。但设计位置（UP1.Z≈166.72）在 dz=-15 时超出边界 11.3mm。即使边界足够，LS 也因为从漂移的 PBD 位置出发，收敛到错误的局部极值而非全局正确解。

### 修复方向

1. 移除硬门槛，对所有 dz 都启用 LS 精化
2. 扩大 LS 边界到 ±30mm 或使用无约束方法
3. 以设计位置而非 PBD 结果作为 LS 初始值（或对设计位置做小步渐进求解）
4. 对 LS 结果验证物理合理性（后倾角变化应 <1°）

## F3: 零长度主销导致 NaN 崩溃（高）

### 现象

当 UP1 = UP2（零长度主销）时，求解器产生 NaN，导致 JSON 序列化失败，服务器返回 500 错误。

### 根因

`_compute_upright_local`（bump.py 第105行）和 `_reconstruct_upright`（第134行）均无零向量保护：

```python
z_axis = vec3(UP1, UP2)
z_axis = z_axis / np.linalg.norm(z_axis)  # UP1=UP2 → 0/0 = NaN
```

NaN 传播到 UP3/UP4，再通过下游角度计算和转向求解器（它们的 `kp_norm < 1e-12` 保护无法捕获 NaN，因为 `NaN < 1e-12` = False）。

JSON 序列化时 `json.dumps({"a": NaN})` 输出 `{"a": NaN}`，不符合 RFC 8259 标准。

### 修复方向

1. 在 `_compute_upright_local` 和 `_reconstruct_upright` 中加入零向量保护
2. 在 `/api/solve` 入口处验证硬点的几何合理性（UP1 ≠ UP2，kingpin > 最小阈值）
3. 对求解结果做 NaN 检查，发现 NaN 时返回错误响应而非崩溃
4. FastAPI 全局配置 `json.dumps(allow_nan=False)` 以防止无效 JSON

## F4: 接地点 Z 坐标脱离地面（中）

### 现象

+25mm 轮跳时接地点 Z=25.43mm（高于地面 25mm），-25mm 回弹时 Z=-22.37mm（低于地面 22mm）。设计状态 Z=2.33mm。

### 根因

`compute_contact_patch`（tire.py 第80-83行）的公式：

```python
z_cp = UP5_np[2] - R_load * cos(camber_rad)
```

计算的是轮胎几何底部（轮心高度 - 加载半径），而非地面接触点。在求解器坐标系中，地面固定在 Z=0，轮跳 dz 只改变轮心高度，不影响地面位置。正确行为是接地点 Z≈0。

| 轮跳 | UP5.Z | z_cp (当前) | z_cp (正确) |
|------|-------|------------|-------------|
| -25 | 125.27 | -22.37 | ≈0 |
| 0 | 150.00 | 2.33 | ≈0 |
| +25 | 172.85 | 25.43 | ≈0 |

### 影响范围

- 偏距和拖距计算不受影响（只用 Y/X 坐标）
- 3D 渲染中接地点显示位置错误（飘离地面）
- 用户查看接地点数据时可能困惑

### 修复方向

将 z_cp 固定为地面高度（默认 Z=0），而非计算轮胎底部：

```python
z_cp = 0.0  # 地面平面
```

## F5: 转向拉杆长度不匹配产生虚假转向（中）

### 现象

PBD 求解后 UP3-FL1 距离偏离设计拉杆长度（dz=+25 时偏差 24mm），导致转向求解器在 rack=0 时仍产生 θ≈0.062 rad（3.5°）的转向角，造成额外的外倾偏移约 0.49°。

### 根因

PBD bump 求解不包含拉杆长度约束（UP3-FL1 距离），UP3 由刚体重建得到。重建后的 UP3 位置与 FL1 的距离偏离设计拉杆长度。转向求解器随后旋转立柱以满足拉杆约束，引入虚假转向。

这是 F1 的衍生故障——UP1 漂移导致刚体重建的 UP3 偏离正确位置。

### 修复方向

F1 修复后此问题应同步改善。若需要额外处理，可在 bump 求解中增加拉杆约束。

## F6: 管件颜色索引删除后偏移（低）

### 现象

管件颜色使用数组索引映射（`FRAME_TUBE_COLORS = {0: "#94a3b8"}`）。删除一条管件后，后续管件的索引全部偏移，导致颜色映射错位。

### 根因

`FRAME_TUBE_COLORS` 以管件在 `FRAME_TUBES` 列表中的索引为 key。删除操作用 `pop(idx)` 从列表中移除管件，但 `FRAME_TUBE_COLORS` 不会同步更新索引。

### 修复方向

使用管件端点列表而非索引作为颜色映射的 key。或在删除管件时重建颜色索引映射。

## 建议修复优先级

1. **P0 — F1: PBD 求解器漂移**：核心运动学求解器问题，影响所有交互操作。需从根本上改善求解收敛性。
2. **P0 — F2: LS 精化不连续**：扫描曲线不连续直接影响工程决策质量。需修复门槛和边界策略。
3. **P1 — F3: NaN 崩溃**：异常输入导致服务器崩溃。需增加防御性编程。
4. **P2 — F4: 接地点 Z 坐标**：影响 3D 渲染和数据展示的准确性。
5. **P2 — F5: 虚假转向**：F1 修复后的衍生改善。
6. **P3 — F6: 管件颜色偏移**：功能性影响低，但数据一致性问题。
